RSC provides unified data management, automated global data protection, backup and recovery options for PostgreSQL clusters, and advanced security features to protect critical data.

RSC provides comprehensive features for protecting and managing PostgreSQL clusters.

Automated global data protection through SLA Domains

The following table details the automated global data protection features for PostgreSQL.
Feature Supported Rubrik CDM versions Description
Protection policies 9.2.1 or later Assigns and manages the SLA Domain protection policies for PostgreSQL clusters to ensure that backup and recovery operations meet defined business needs, Recovery Time Objective (RTO), or Recovery Point Objective (RPO) requirements.

Backup and recovery

The following table details the backup and recovery features of PostgreSQL.
Feature Supported Rubrik CDM versions Description
On-demand backups 9.2.1 or later Supports manual backups of PostgreSQL clusters as needed, outside of predefined schedules.
Cluster-level backup 9.2.1 or later Supports comprehensive backups at the PostgreSQL cluster level, capturing all clusters and associated data within the cluster.
Archiving 9.2.1 or later Enables long-term retention of PostgreSQL snapshots by tiering them to lower-cost archival storage, such as cloud object storage, for compliance and cost efficiency. For more information, see Archiving for PostgreSQL snapshots.
Multiple archival locations 9.5.1 or later Supports up to two archival targets for a single PostgreSQL cluster to enhance data redundancy and compliance. For more information, see Multiple archival locations for PostgreSQL.
Write-Ahead Log (WAL) file retention on PostgreSQL host 9.5.1 or later Enables the configuration of a local retention period for WAL files on the PostgreSQL host after backup. By default, the PostgreSQL server deletes WAL files immediately after backup. For more information, see WAL file retention on PostgreSQL host.
Download from archival 9.5.1 or later Downloads PostgreSQL snapshots and log snapshots from an archival location for recovery to local storage on the Rubrik cluster. For more information, see Archiving for PostgreSQL snapshots.
Archival reader (Archival Disaster Recovery) 9.5.0 or later Enables a dedicated Rubrik cluster to connect to an archival location as an archival reader and recover PostgreSQL snapshots for disaster recovery. In standard archival reader mode, the reader cluster cannot simultaneously serve as a replication target.

Starting with Rubrik CDM version 9.6.0, you can configure a replication target cluster to also act as an archival reader.
Snapshot replication 9.2.1 or later Replicates PostgreSQL backup snapshots to other Rubrik clusters for disaster recovery, ensuring offsite data availability.
Download replicated snapshots 9.5.1 or later Downloads replicated PostgreSQL snapshots from the replication target cluster for recovery if the snapshots are not available on the source cluster. For more information, see Replication for PostgreSQL snapshots.
Replication pair coexistence with archival reader 9.6.0 or later Enables you to configure the archival reader and replication pair simultaneously on the same Rubrik cluster to protect a PostgreSQL cluster. For more information, see Archival reader and replication pair coexistence.
Retention lock 9.4.0 or later Provides compliance and legal requirement mechanisms to enforce immutable retention periods for backups, preventing unauthorized deletion or modification of data.

Retention lock is available during SLA Domain configuration. However, the retention period in a retention-locked SLA Domain cannot be reduced, which can prevent premature snapshot deletion.
RSC-based automated recovery 9.4.1 or later Provides an RSC workflow to recover snapshots and logs.
Note:
RSC supports manual recovery of PostgreSQL clusters prior to Rubrik CDM version 9.4.1.
Log snapshot visibility 9.6.0 or later Displays the log snapshots that cover a recovery point on the snapshot calendar and those required for recovery on the Recovery Details page. For more information, see PostgreSQL log snapshot visibility.
High Availability (HA) 9.6.0 or later For Rubrik CDM versions earlier than 9.6.0, RSC protects PostgreSQL clusters in a primary and standby HA setup by maintaining two separate backup chains, ensuring backup continuity upon failover.

Starting with Rubrik CDM version 9.6.0, RSC protects an HA setup as a single HA cluster group. RSC identifies the primary and standby roles, links the clusters into the group, and updates the roles automatically during a failover. The primary and standby PostgreSQL nodes must back up data to the same Rubrik cluster. To ensure uninterrupted history and operational efficiency, RSC maintains a single, unified backup chain for the entire HA pair across failover events.

For more information, see Configure High Availability for a PostgreSQL cluster.
Multiple channel backup 9.6.0 or later Distributes backup data transfer across multiple Rubrik cluster nodes over a secure thrift channel, increasing backup throughput for large PostgreSQL clusters.

Supports end-to-end encryption for data at rest and data in transit by transitioning the data path to secure thrift.

Adopting or migrating to the multiple channel data path depends on when and how you onboard your PostgreSQL clusters:
  • New or re-registered clusters: When adding or re-registering PostgreSQL clusters on a Rubrik cluster running CDM 9.6.0 or later, RSC automatically uses the improved backup data path.
  • Pre-existing clusters: Migrating a pre-existing PostgreSQL cluster to the multiple channel data path requires deleting the PostgreSQL cluster from protection and re-registering it on a Rubrik cluster running CDM version 9.6.0 or later.

Security and access control

The following table outlines the security and access control features for PostgreSQL.
Feature Supported Rubrik CDM versions Description
Role-based Access Control (RBAC) 9.2.1 or later Provides granular permissions to administrators to manage data protection operations for PostgreSQL workloads, ensuring security and compliance with organization access policies.
Quorum Authorization 9.2.1 or later Enforces authorized approvals to modify data protection decisions, such as policy changes and deletion requests, to prevent unauthorized actions and protect data integrity.
Secure connectivity 9.2.1 or later Establishes secure communication channels for data transfer and management operations between PostgreSQL clusters and RSC.

The methods for secure communication and data transfer between PostgreSQL clusters and RSC are as follows:

  • Authentication: Using either socket-based or TCP-based authentication for management and control operations, and configuring SSL for secure connectivity.
  • Backup data transfer: Transferring backup data using NFS for clusters on Rubrik CDM versions earlier than 9.6.0, or using the secure thrift channel for clusters on Rubrik CDM 9.6.0 or later.
  • WAL file transfer: Transferring WAL files over secure thrift.
  • Full data recovery: Restoring data over NFS for clusters on Rubrik CDM versions earlier than 9.6.0, or using the secure thrift channel for clusters on Rubrik CDM 9.6.0 or later.
  • Log recovery: Restoring logs using the secure thrift protocol.
User notes Not applicable Provides the ability to add descriptive notes to PostgreSQL objects for audit and tracking purposes. For more information, see User notes for PostgreSQL.
Legal hold 9.5.0 or later Retains snapshots indefinitely for litigation requirements. Placing a snapshot on legal hold prevents an SLA Domain from expiring the snapshot until you explicitly remove the legal hold. For more information, see Legal hold for PostgreSQL snapshots.
