Creating a custom role for MongoDB

Create a role with RBAC privileges for managing MongoDB workloads. These privileges provide granularity for determining which permissions an RSC user has for performing specific actions on specific objects.

Procedure

  1. Log in to RSC.
  2. Click and select Settings.
    The Settings menu appears.
  3. Click Users & Access and select Roles.
    The Roles page appears.
  4. Click Create Role.
    The Create Role wizard appears.
  5. Click Custom role.
  6. Under Data Management Privileges, click Configure.
    The Data Management Privileges page appears.
  7. Select By object type and click Next.
  8. Select MongoDB.
    RSC displays the All protectable objects, All recovery targets, and Full privileges options. By default, all the permissions are selected within Full privileges. You can customize the privileges on specific objects by editing any of these options.
  9. Determine the objects, targets, and privileges for which you are granting permission and click Done.
    OptionDescription
    All protectable objects

    Use this option to select all existing and future objects or specific MongoDB objects you want to protect using this custom role.

    To assign specific permissions such as view, protection, and recovery to this custom role, use the Full privileges option.

    Using the Search by name field, you can narrow the search by specifying the object name.
    All recovery targets Use this option to select the recovery targets where you want to recover the snapshots. Users with this custom role can recover to the selected recovery targets.

    To assign specific permissions to the selected recovery targets, use the Full privileges option.

    Using the Search by name field, you can narrow the search by specifying the target name.
    Full privileges Use this option to set up data management privileges for the selected source objects and recovery targets.

    For example, you can select the View, Protection, and Recovery headings to grant all the privileges in these categories.
  10. Click Next.
    The Assign Datacenter Archival Locations page appears.
  11. Determine which data center archival locations you are selecting.
    OptionDescription
    Select all existing and future archival locations

    Use this option to select all existing and future archive locations. By doing so, users with this custom role can use all current and future archival locations in RSC to archive snapshots of the protected MongoDB objects.

    By default, all archival locations have the view-only permission. However, you can add permissions for this custom role to add, edit, delete, or manage archival locations.
    Select specific archival locations Use this option to select specific archival locations where you want the user with this custom role to archive the snapshots of the protected MongoDB objects.

    Filter the search by selecting from the Storage type, Archival Location Type, Rubrik Cluster, and Status lists.
  12. Click Next.
    The Select SLA Domains page appears.
  13. Optional: Turn on Self-Service.
    Turning on the self-service option removes the ability to select specific SLA Domains and specifies the manage permission for all existing and future SLA Domains.
  14. Determine the SLA Domains for which you want to grant permissions for this custom role.
    OptionDescription
    Select all existing and future SLA Domains Use this option if you want users with this custom role to have permissions on all existing and future SLA Domains. By doing so, the users with this custom role can manage these SLA Domains and assign them to the protectable MongoDB objects.

    Additionally, you can use the dropdown list to select specific permissions related to the management of SLA Domains. Evaluate the available options and select the one that aligns with your requirements.
    Select specific SLA Domains Use this option to select specific SLA Domains. Select the SLA Domains from the list you want this custom role to have access to, and click the Edit icon to assign the Manage permission, if required.

    You can filter the search by selecting values from the Creator Org and Managed By lists.
  15. Optional: For specific SLA Domains, select Include Don't Protect if you want this protection setting to appear when managing protection for a MongoDB object.
  16. Optional: For specific SLA Domains, select Include Clear current SLA Domain if you want this protection setting to appear when managing protection for a MongoDB object.
  17. Click Done.
    The Create Role wizard reappears.
  18. Click Next.
    The Role Details page appears.
  19. In Role name, enter a name for the custom role.
  20. Optional: In Role description, enter a description for the role.
  21. Optional: Turn on Synchronize Role to CDM Clusters to synchronize the role with Rubrik CDM.
    You can synchronize roles only to CDM version 9.3.0 and later.
    The Role Details section displays the number of chosen clusters based on the permissions and clusters selected in the Data Management section. It also displays the number of connected and disconnected clusters. You can click the number to get a list of these clusters.
  22. Click Create.
