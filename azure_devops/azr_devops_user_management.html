RSC user management for Azure DevOps

Designating specific users with appropriate privileges and roles in RSC enhances security for managing Azure DevOps organization.

Designating specific users with the appropriate privileges and roles for managing Azure DevOps organization within RSC enhances security. To achieve this, you create user accounts in RSC for individuals you identify as part of your data management team and assign appropriate roles to each of those accounts.

You can assign specific privileges to roles, and then assign those roles to user accounts. There are two ways to create a role:

  • Creating a role by selecting from pre-configured role templates provided by RSC
  • Creating a custom role to select individual privileges based on your requirements

Pre-configured role template

The pre-configured role templates relevant for Azure DevOps protection are:
  • Azure Cloud Account Owner: An RSC user with this role can manage all aspects of Azure DevOps organizations. Additionally, this role is required to configure backup location and Exocompute.
  • Backup Administrator: An RSC user with this role can manage every aspect of backup and recovery operations on RSC for Azure DevOps organizations.

Custom role

A custom role provides the flexibility to select specific privileges for Azure DevOps organizations according to your requirements. You can create custom roles for different operations, such as:
  • Azure DevOps organization management
  • Recovery operations for all Azure DevOps organizations

RBAC for Azure DevOps custom roles

Role-based Access Control (RBAC) for Azure DevOps organization protection in RSC enables you to create custom roles to assign precise access privileges on your Azure DevOps resources. This capability is important for organizations, particularly those with decentralized or federated teams, to ensure security and maintain separation of duties.

RBAC for Azure DevOps organization protection provides the following key features for precise access management:
Feature Description
Granular access management You can assign roles and privileges to manage the protection for specific projects or repositories. This enables individual business units to manage backups for their code while restricting access to other parts of the organization.
Enhanced security You can significantly enhance security by configuring precise privileges, ensuring users only have access to necessary resources through improved granularity of access controls.
The following practical use cases illustrate the benefits of RBAC for Azure DevOps organization protection:
Use case Description
Azure DevOps organization–level RBAC Central administrators can manage SLA Domains for the entire Azure DevOps organization within RSC.
Azure DevOps project-level RBAC You can assign roles to grant or restrict access to manage protection, such as backup and recovery for all repositories, within a specific project.
Azure DevOps repo-level RBAC You can fine-tune access by assigning roles to manage the protection of individual repositories. This enables specific development teams to manage the protection of their most critical or highly sensitive code.
