Db2 RSC-based recovery prerequisites

To ensure a successful recovery using RSC, the Db2 environment must meet specific requirements.

The following table provides details about the prerequisites for Db2 recovery using RSC.
Prerequisite Description
Operating systems Only Linux and AIX hosts are supported for UI-based recovery.
Storage configuration RSC only supports recovery for databases that use automatic storage tablespaces. Databases with manually managed storage tablespaces must be recovered using the CLI.
Instance type Only standalone and partitioned database restores are supported. HADR and pureScale source databases are not supported for Db2 UI-based recovery.

Note: Restores of partitioned databases are disabled by default prior to version 9.5.2 and can be enabled by contacting Support.
Database states If you are restoring to an existing database, you must deactivate the target database before starting the recovery.
Naming conventions Target database names must be 8 characters or less.
Target database protection When restoring to the original database or to a different existing database, the target database must not already be protected by an SLA Domain.
Partition count When restoring to a different existing database, the partition count must match between the source snapshot and the target instance.
Catalog partition number When restoring to a different existing database, the catalog partition number must match between the source snapshot and the target database.
Permissions The Db2 instance user must have read, write, and execute permissions for the temporary log target and database directories specified during the workflow.
