Searching Amazon DynamoDB snapshot records

Search for specific records in Amazon DynamoDB snapshots using partition key and optional attribute filters, then preview or export the matched results.

Before you begin

Before you search DynamoDB snapshot records, ensure the following:

  • Your organization has an active Backup as a Service (BaaS) license and the DynamoDB table is protected under an RSC-managed SLA Domain. For tables that are not protected under an RSC-managed SLA Domain, the Records tab and the Recover specific records option do not appear.
  • You have at least one RSC permission on the DynamoDB workload: Browse snapshot and object contents, Restore over original, Download files, Export files, or Export snapshots. To view unmasked record values, you need one of the following permissions: Download files, Export files, or Export snapshots. For more information, see Required RSC permissions for DynamoDB granular recovery.

About this task

This topic describes a feature or features that Rubrik is gradually rolling out to customers.

You can use the Records tab to search across a range of snapshots when you do not know which snapshot contains the required records, or when you want to compare record changes across multiple snapshots. If you already know which snapshot to recover from, you can instead click Recover for that snapshot on the Overview tab and select Recover specific records. The search in that path is scoped to the selected snapshot only. For instructions, see Recovering specific Amazon DynamoDB records from a snapshot.

Procedure

  1. Log in to RSC.
  2. Click and select Data Protection.
    The Data Protection dashboard appears.
  3. On the navigation bar, click Inventory.
    The Inventory page appears.
  4. Click the AWS DynamoDB inventory card.
    The AWS DynamoDB page appears.
  5. Select the DynamoDB table you want to search.
    The Details page appears, showing table details such as the assigned SLA Domain, size, regions, and available snapshots.
  6. Click the Records tab.
    The Records search form appears on the left with an empty results panel on the right.
  7. In the partition key field, enter one or more partition key values.

    The field label shows the name of the partition key attribute of the table. For example, item_id . You can search for multiple values by entering a comma-separated list of partition key values. For a larger list, you can click Upload CSV and select a CSV file that contains one partition key value per row.

    Searching by Global Secondary Index (GSI) values is not supported.

  8. In Snapshot Range, set the start and end dates for the search.
    RSC searches only snapshots taken within this date range.
  9. Optional: Turn on Show Sensitive Data to view unmasked record values in the results.
    Show Sensitive Data is turned off by default, so RSC masks all record values, including the partition key and sort key. Masked values appear as five asterisks regardless of the actual value length. You can show or hide sensitive data for each snapshot independently.
  10. Optional: Click Advanced Filters to add attribute filters that narrow results beyond the partition key.
    Note:
    Advanced Filters is available only for tables that have a sort key or at least one Local Secondary Index (LSI). Otherwise, Advanced Filters is unavailable and displays the message: This table has no additional attributes to filter on.
    1. In Field, select an attribute column.
      The available columns are the sort key and any LSIs defined on the table.
    2. In Operator, select an operator.
      The available operators depend on the data type of the attribute:
      • String and binary attributes: Equals, In, Contains, Begins with, Is empty, and Is not empty
      • Numeric attributes: Equals, In, Greater than, Less than, Greater than or equal to, Less than or equal to, Between, Is empty, and Is not empty
    3. In Value, enter the filter value without surrounding quotation marks and then press Enter to commit the value.
      The Apply button is not enabled until you commit the value.
    4. To add another filter, click Add Filter and repeat.
  11. Click Apply.
    Note:
    If no records match, the panel shows: No matching records found. Try removing a filter or verifying your partition key values.
    RSC searches across all snapshots in the selected date range. The results panel displays a list titled Matching Records Across N Snapshots, where each row shows a snapshot date and time, its storage location, and a View link.
  12. In the results list, click View for the snapshot you want to inspect.
    The Recover Records wizard opens at step 1, displaying up to 50 matching records from that snapshot as formatted JSON. If a snapshot has fewer than 50 matches, the wizard displays all of them. RSC masks all record values, including the partition key and sort key, unless you turned on Show Sensitive Data earlier in this procedure.
  13. Optional: To view unmasked record values, turn on Show Sensitive Data.
    RSC searches again and displays unmasked values.
  14. Optional: To export records, click Export and select an export option.
    OptionDescription
    Export Preview (JSON) Downloads up to 50 records shown in the preview directly to your browser as a .json file. The download starts immediately. This action does not generate an RSC event.
    Export All Records (JSON) Initiates a background export job that packages all matching records. A banner confirms the job has started. When the job completes, navigate to Events > File Preparation Center and download the .ndjson file.

Results

You can now review the matched records and choose to restore them in place or export them. To restore records to the original table, you can click Next in the wizard. For the full restore procedure, see Restoring Amazon DynamoDB records in place.
