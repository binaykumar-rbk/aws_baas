Managing protection for filesets

Manage protection for filesets on the failover cluster services by assigning or removing an SLA Domain.

About this task

A fileset in a failover cluster service inherits the SLA Domain from the parent service unless an SLA Domain is directly assigned to the fileset.

Procedure

  1. Log in to RSC.
  2. Click and select Data Protection.
    The Data Protection dashboard appears.
  3. On the navigation bar, click Inventory.
    The Inventory page appears.
  4. Click a fileset card based on the OS type of the host.
    • Windows filesets
    • Linux & Unix filesets
    The corresponding filesets page appears.
  5. Click the Failover Clusters tab.
    A list of failover clusters appears.
  6. In the Name column, click the name of a failover cluster.
    A list of failover cluster services appears.
  7. Select a failover cluster service.
    You can select multiple services.
  8. Click Manage Protection.
    The Failover cluster service wizard starts.
  9. Select Assign SLA Domains to filesets of the service.
  10. Click Next.
    The Select fileset page appears.
  11. Optional: Click the + icon to create a fileset.
    After creating a fileset, the Select fileset page displays the new fileset.
  12. Select a fileset.
  13. Click Next.
    The Assign SLA Domain page appears.
  14. Select a protection option.
    OptionDescription
    SLA Domain Assigns the selected SLA Domain to the object.
    Clear existing assignment Removes the current SLA Domain assignment from the object. Object inherits SLA Domain from the parent object.
    Don't protect Excludes the chosen objects from all further SLA Domain assignments.

    Provides options for existing snapshot retention.
  15. (Don't protect) In Existing snapshot retention, choose an option to retain the existing snapshots.
    OptionDescription
    Use current SLA Domain for retention The snapshots are retained based on the retention policy of the current SLA Domain.

    This is the default option.
    Keep forever The snapshots are retained until they are manually deleted.
    Expire immediately The snapshots are deleted from the Rubrik cluster.
  16. Optional: Select Direct Archive to enable Direct Archive for the fileset.

    Direct Archive is only available when the fileset is assigned to an SLA Domain that specifies an archival location.

  17. Optional: (Linux and Unix) Select Symlink to resolve symbolic links for Linux and Unix filesets.
    Enabling this option could increase the backup time for Linux and Unix filesets.

    If a symbolic link is not resolved, it appears as a file, rather than as a folder, in the UI. Symbolic links in Linux and Unix filesets that point to a directory in a different fileset are not resolved.

  18. Click Next.
    The confirmation page displays a summary of SLA Domain changes and options to apply changes to existing snapshots. The options to apply changes to the existing snapshots are not displayed when the Don't protect option is selected.
    A Confirmation page appears.
  19. Optional: For Apply changes to existing snapshots:
    • Turn on Apply changes to the existing snapshots.
    • Turn off this option to keep the retention policy of existing snapshots unchanged.
  20. Optional: (Apply changes to existing snapshots) For Include on-demand and downloaded snapshots:
    • Select the setting to apply changes to the retention policy of on-demand and downloaded snapshots.
    • Clear the setting to keep the retention policy of on-demand and downloaded snapshots unchanged.
  21. Click Assign.

Results

RSC processes the specified SLA Domain assignment options for filesets and manages protection for the failover clusters.
