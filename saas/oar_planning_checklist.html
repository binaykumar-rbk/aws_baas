Planning checklist for Orchestrated Recovery

You can use this checklist to confirm the prerequisites and configuration decisions for a Recovery Plan before you create one.

Environment prerequisites

You must meet the following prerequisites before you create a Recovery Plan:

  • For data center workloads, the same source Rubrik cluster protects all virtual machines in the plan. For cloud-native workloads, all virtual machines in the plan belong to the same source Azure subscription and region, or to the same source AWS account and region.
  • All virtual machines in the plan are the same workload type. A Recovery Plan cannot mix VMware virtual machines, AHV virtual machines, Azure virtual machines, and AWS EC2 instances.
  • For VMware virtual machines: Every virtual machine in the plan has VMware Tools installed and running.
  • For VMware disaster recovery: You have configured the vCenter privileges required for agentless network reconfiguration at the target site.
  • For AHV virtual machines: You have added Nutanix Prism Central to RSC and turned on data protection for the Nutanix disaster recovery workflow.
  • You cannot add virtual machines that were part of a vCloud Director vApp to a vSphere Recovery Plan.

For additional requirements, see Recovery Plan requirements and settings.

Replication prerequisites for disaster recovery

For disaster Recovery Plans, you must have the following in place before you create the plan:

  • You have configured replication between the source and target Rubrik clusters.
  • The SLA Domain protecting source virtual machines specifies the target cluster as its replication target. A mismatch results in the Inconsistent target location status after you create the plan.
  • To support a failback after a production failover, the SLA Domain at the target must specify the original source cluster as its replication target.

Resource mapping decisions

You need the following information before you create a Recovery Plan. The Create Recovery Plan wizard asks for these details:

  • Target compute, storage, and network resources at the recovery site.
  • Network configuration method: Entire Network, which remaps all IP settings; MAC Address Only, which retains the MAC address; or None, which skips network reconfiguration. Test failover and production failover might require separate network configurations if the target networks differ.
  • For VMware disaster recovery: whether to use pre-seeded disks, which provide a faster RTO but consume storage continuously, or on-demand Export, which uses no ongoing storage but has a longer RTO. See Pre-seeding disks for disaster recovery and Sizing, RTO, and RPO.
  • For datastores with Storage DRS disabled: The wizard shows individual child datastores rather than the datastore cluster. You must identify the individual target datastore before creating the plan.

Workload assignment rules

A virtual machine can belong to one disaster Recovery Plan or one in-place Recovery Plan, but not to both. You can include a virtual machine in a cyber recovery plan alongside a disaster or in-place plan, and in multiple cyber recovery plans.

Reviewing existing Recovery Plans before adding virtual machines to a new plan helps avoid assignment conflicts.
