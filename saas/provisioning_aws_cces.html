Provisioning Rubrik Cloud Cluster Elastic Storage on AWS

Provision and deploy Rubrik Cloud Cluster Elastic Storage on Amazon Web Services from RSC to protect applications and data on Amazon EC2 instances within a virtual private cloud.

Before you begin

If a cloud account for Rubrik Cloud Cluster Elastic Storage does not already exist, create a cloud account, selecting Cloud Cluster Elastic Storage as the use case.

Complete the prerequisites as described in Prerequisites for Rubrik Cloud Cluster Elastic Storage on AWS.

About this task

This topic describes a feature or features that Rubrik is gradually rolling out to customers.

Procedure

  1. Log in to RSC.
  2. Click and select Data Protection.
    The Data Protection dashboard appears.
  3. On the navigation bar, click Infrastructure > Clusters.
    The Clusters (Rubrik Secure Vaults) page appears.
  4. Click and select Create Rubrik cluster.
    The Select a Rubrik cluster type wizard appears.

    You can also launch this wizard from the Inventory page.

  5. Click Next.
    The Select a cloud provider page appears.
  6. Click AWS and then click Next.
  7. In AWS Account, select an AWS account or click to add an account.
  8. In Region, select the region in which to deploy the cluster.
  9. Optional: If you are configuring multiple availability zones, click Availability Zone Resiliency.
    This option appears only if the selected region supports three or more availability zones.
  10. In Availability Zone, select a zone.

    If you are configuring multiple availability zones and the region has exactly three zones, RSC automatically selects all three.

  11. Click Next.
  12. In Rubrik Cluster Name, enter a name for the Rubrik Cloud Cluster Elastic Storage deployment.
    The tooltip for this field explains the guidelines for naming Rubrik clusters.
  13. In DNS Nameservers, enter the IP address of a DNS nameserver or accept the default IP address, 8.8.8.8.
  14. Optional: To add DNS nameservers, click Add.
  15. Optional: In DNS Search Domains, enter the name of a DNS search domain.
  16. In NTP Servers, enter the address of an NTP server or accept the default server, pool.ntp.org.
  17. Enter and confirm the credentials for the administrative user account and then click Next.
  18. Select the processor type.
  19. In Instance type, select an instance type based on the required capacity.
  20. From Number of Nodes, select the number of nodes to provision.
    Rubrik Cloud Cluster Elastic Storage runs on a single node or on three or more nodes. Rubrik CDM versions 9.0.1 and later support single-node configuration. Rubrik does not support a two-node configuration.

    If you are configuring multiple availability zones, you need at least three nodes with one availability zone for each node. The cluster distributes added nodes equally across the selected zones. For example, a 6-node cluster places two nodes in each of the three selected zones.

  21. Optional: Select Enable dynamic scaling.
    This option requires Rubrik CDM version 9.5 or later. Selecting this option optimizes compute costs by automatically adjusting the number of active nodes based on workload demand.
  22. In Instance profile, select the instance profile for Rubrik Cloud Cluster Elastic Storage.
    The instance profile is an AWS container object that holds one IAM role and attaches it to the EC2 instance so that Rubrik cluster nodes can access AWS without storing access keys.

    When you create an IAM role by using the AWS Management Console, an instance profile with the same name is created. When you create the IAM role by using the CLI or API, the instance profile might have a different name from the IAM role.

  23. In Virtual Private Cloud, select the virtual private cloud (VPC) for the AWS Cloud Cluster.
  24. In Subnet, select the subnet in which to deploy Rubrik Cloud Cluster Elastic Storage.
    If you are configuring multiple availability zones, select a subnet for each zone.
  25. In Security Groups, select the security groups to apply to the nodes on the cluster.
  26. In S3 bucket, enter the S3 bucket name in which to store data for Rubrik Cloud Cluster Elastic Storage.
    If the existing bucket does not have object locking enabled, create a new bucket with object locking enabled.
  27. Optional: Select Enable immutable cluster storage if you want to protect snapshots against accidental deletion or malicious activity, such as ransomware attacks.
    RSC turns on this setting by default.
  28. In Key ARN, enter the ARN of the AWS KMS key that you want to use to encrypt the recovery package.
    The AWS KMS key protects the cluster recovery package before the cluster writes the data to cloud storage.
  29. Optional: Select On Failure, save resources for support debugging.
  30. Optional: Select Use placement groups if your backup and restore jobs are I/O-intensive and you want to increase throughput.
    This option is not available when you use multiple availability zones because placement groups are confined to a single availability zone.
  31. Click Next.
    RSC validates the configuration and then opens the Confirmation page.
  32. Review the configuration summary and click Submit.

Results

RSC provisions and deploys Rubrik Cloud Cluster Elastic Storage on AWS using the specified configuration.

If cluster provisioning fails, click Retry to re-deploy the cluster with the original configuration pre-filled.

If RSC cannot register the cluster, register the cluster manually. For more information, see the Rubrik Cloud Cluster Elastic Storage Setup Guide.
