Creating a custom SLA Domain

Create a custom SLA Domain to define and customize workload protection and management policies.

Before you begin

You must ensure the following:
  • Review the settings for the specific object types listed in Supported features for RSC workloads.
  • Select the workload types that support archiving and replication.
  • Enable Quorum Authorization (QAuth) if you plan to use retention lock.
  • Assign required IAM permissions to the AWS account role to support native AWS EBS Snapshot Lock. For more information, see Required permissions for native AWS protection.

About this task

RSC displays options for custom SLA Domains based on the selected workload type, as each type has unique properties to protect its objects.

Procedure

  1. Log in to RSC.
  2. Click and select Data Protection.
    The Data Protection dashboard appears.
  3. On the navigation bar, click SLA Domains.
    The SLA Domains page appears.
  4. Click Create SLA Domain.
    Ensure that you understand the provided information about SLA Domains, including snapshot frequency and retention policies, before proceeding to create one.
    The Create SLA Domain wizard appears.
  5. Click Start on the Create SLA Domain page that describes SLA Domains.
    Selecting Don't show again skips this page the next time you create SLA Domains.
  6. Select the workload types and click Next.
  7. Optional: Turn on Retention Lock.
    OptionDescription
    Governance mode Requires quorum authorization.

    Governance mode retention lock appears by default and requires quorum authorization.
    Compliance mode

    This mode does not require quorum authorization.

    Selecting the mandatory acknowledgment enables you to proceed to the next step.

    To enable compliance mode retention lock, contact Rubrik Support.
    Note:
    Enabling Retention Lock for Amazon EC2 and EBS workloads triggers native AWS EBS snapshot locking. For detailed information on immutability requirements and lock failure behavior, see Creating a retention-locked SLA Domain.
  8. Click Next.
  9. Enter a snapshot frequency and a corresponding retention period.
    The snapshot frequency categories are optional, but at least one category must have a value.
  10. Optional: Turn on the Snapshot window.
    You can configure the snapshot window to take the first full snapshot and the subsequent snapshots within a specific time frame. By default, RSC takes the first full snapshot at the first opportunity and subsequent recurring snapshots at any time of the day.

    Workloads managed by a Rubrik cluster use the timezone of that Rubrik cluster. Workloads managed by RSC use the UTC timezone.

  11. Optional: Select the checkbox to terminate in-progress snapshots outside the snapshot window.
    When you select this check box, RSC automatically terminates the backup jobs exceeding the specified snapshot window and reattempts them during the next snapshot window. You must configure at least one snapshot window to enable this check box.
    Note:
    RSC supports the termination of snapshots exceeding the snapshot window only for data center workloads running Rubrik CDM version 9.5.1 and later.
  12. For cloud native workloads, in First full snapshot, select a start type.
    OptionDescription
    First opportunity The first full backup occurs by default when a data source has been added.
    Custom range The first full backup occurs within a specified window.
  13. Click Next.
    The Archival and Replication page appears.
  14. Optional: Select Archival.
    Selecting this option configures archival locations for disaster recovery and long-term retention.

    Click Learn more to explore configuring archival locations for disaster recovery and long-term retention.

  15. Optional: Select Replication.
    Selecting this option configures replication between source and target clusters for data protection and disaster recovery.
    Click Learn more to read about setting up replication pairings between source and target clusters.
  16. Click Next.
    The Archival Parameters page appears.
  17. For archiving, configure the source retention, archival location, snapshot frequency, and the archival threshold.
    For Snapshot Frequency, you can select different frequencies for different archival locations. You must select the maximum frequency for at least one archival location.

    For the Archival Threshold, you can select instant archive or specify the number of days from when you want your archiving to begin. You can configure multiple archival locations.

    Note:
    For data center database workloads, RSC does not tier the log snapshots to offline storage tiers. Only data snapshots are tiered based on the customer-specified policies.
  18. For instant tiering, select the archival location.
  19. Click Next.
    The Object-Specific Settings page appears.
  20. Configure object-specific details based on the selected workloads and click Next.
    Amazon DynamoDB tables automatically enable continuous backups. Disabling these backups or changing the retention period in your AWS Management Console can increase your storage and consumption costs. To prevent these higher expenses, keep continuous backups enabled in your AWS Management Console.

    The Workload-specific settings for SLA Domains topic provides more details about the settings available for a specific workload.

  21. For Amazon DynamoDB, retrieve the KMS Key alias from your AWS account and enter the details to configure primary backup encryption.
    Important:
    To ensure successful encryption of the backed-up table data, the specified KMS key alias must be present and correctly configured in the target AWS account and the target AWS region. While different accounts and regions have unique underlying KMS keys, these accounts and regions can share a common KMS key alias for this purpose.
  22. Click Next.
    The Confirmation page appears.
  23. In SLA Domain name, enter a name to identify the SLA Domain.
  24. Optional: In Add Description, enter a description to provide additional context for the SLA Domain.
  25. Review the configuration details and click Create.
    A message appears confirming that you have successfully created an SLA Domain.

Results

RSC creates a custom SLA Domain for the selected workload types.
Related concepts
  • Snapshot window
    You can configure an SLA Domain to include a snapshot window.
  • Instant tiering of snapshots
    The instant tiering feature archives data immediately to the specified cold storage tier in the cloud. This approach is ideal for optimizing storage costs when data restoration is a rare requirement.
