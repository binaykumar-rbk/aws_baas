Rubrik Cloud Vault storage tiers

Information about Rubrik Cloud Vault storage tiers, which include backup, archive, and recovery tiers, each with corresponding retention periods, access times, and immutability features to meet various data storage requirements.

This topic describes a feature or features that Rubrik is gradually rolling out to customers.

The following table describes the purpose of each storage tier.
Attribute Backup tier Recovery tier Archive tier Notes
Use case Immediate recovery needs for cloud-native and data center workloads. Advanced security operations, such as orchestrated recovery. Long-term data retention and compliance. NA
Required snapshot retention period At least 30 days At least 30 days
  • At least 180 days for RCV locations on Azure and AWS
  • At least 365 days for RCV locations on GCP

Rubrik rejects the assignment of the Rubrik Cloud Vault (RCV) archival location to an SLA Domain if the archival parameters of the SLA Domain do not meet the snapshot retention requirements.

Deleting an RCV archival location might result in some snapshots that do not meet retention requirements, leading to an early deletion penalty.

Not renewing an RCV subscription might result in an RCV location storing snapshots that cannot meet the retention period, leading to an early deletion penalty.
Time to access archived snapshots Minutes or hours Minutes or hours Several hours to days NA
Blob-level immutability or object-level immutability Yes (for the retention period of the snapshots) Yes (for the retention period of the snapshots) Yes (for the retention period of the snapshots) The following objects are protected in RCV with blob-level or object-level immutability enabled by default:
  • Data center objects protected in RCV locations created on Rubrik clusters running Rubrik CDM version 9.1 or later
  • Cloud-native objects
  • Rubrik NAS Cloud Direct objects

For data center objects, blob-level immutability is available only for Rubrik clusters running Rubrik CDM version 9.1 or later. For Rubrik clusters running an earlier version, only container-level immutability is available for backup tier locations.
Container-level immutability or bucket-level immutability Yes (for up to 150 days) NA NA Immutable storage in the RCV is automatically terminated at the end of your subscription period and is limited to a maximum of 150 days. This is applicable only to data center RCV locations on Azure.
Redundancy

For data center and cloud-native RCV locations on Azure, RSC supports the following redundancy options:

  • Single zone
  • Multi-zone
  • Multi-region

For NAS CD RCV locations on Azure, RSC supports only single zone redundancy.

For RCV locations hosted on AWS, RSC supports single zone and multi-zone redundancy.

For RCV locations hosted on GCP, redundancy is always multi-zone.

For cloud-native RCV locations on Azure, RSC supports the following redundancy options:

  • Single zone
  • Multi-zone
  • Multi-region

For cloud-native RCV locations hosted on AWS, RSC supports Single zone and Multi-zone redundancy.

 Redundancy for archive tier locations is determined by the cloud platform and is read-only.
  • Azure: Single zone
  • AWS: Multi-zone
  • GCP: Multi-zone
Note:
Archive tier licenses apply to all supported cloud platforms regardless of the redundancy type.
