RSC-managed IaaS workloads

RSC provisions and manages the AWS resources required to back up Infrastructure as a Service (IaaS) workload hosts on your behalf, and uses AWS Systems Manager to install the Rubrik Backup Service on the hosts, when you use an RSC-managed deployment.

Note:
Protecting Infrastructure as a Service (IaaS) workloads in an RSC-managed AWS deployment requires Rubrik CDM version 9.6.1 or later.
To protect an IaaS workload host, RSC performs the following actions in your AWS account:
  • Sets up a private network connection: The private connections are between each VPC that contains protected hosts and Rubrik, using an interface VPC endpoint and a dedicated security group.
  • Installs the Rubrik Backup Service (RBS) on each host: Rubrik uses the AWS Systems Manager (SSM) Run Command in a Rubrik-owned SSM document to install RBS. You do not need to log in to the host or install software yourself.

Rubrik applies the permissions for both actions from the CloudFormation stack you deploy when you add the AWS account.

Resources Rubrik creates in your account

The following table lists the resources that Rubrik creates in your AWS account to support IaaS workload protection.
Resource Name Created Purpose
SSM Command document rubrik-cces-baas-onboard Once per AWS account and region Holds the scripts RSC runs on your hosts
Interface VPC endpoint rk-cces-vpce-<id> Once per VPC for each Rubrik backup cluster Private connection from your hosts to Rubrik
Security group rk-cces-vpce-sg-<id> Once per VPC for each Rubrik backup cluster Enables your hosts to reach the endpoint

Rubrik does not modify your VPCs, subnets, route tables, network ACLs, Route 53 zones, or your own security groups. The only changes Rubrik makes to your existing resources are on the hosts you choose to protect.

Private network connection to Rubrik

RSC connects protected hosts to their Rubrik backup cluster over AWS PrivateLink. Backup traffic flows from your hosts to the interface VPC endpoint and then privately to Rubrik. The connection is private to your account, carries no other customer traffic, and never traverses the public internet.

Rubrik creates the following resources in your account:
  • Interface VPC endpoint: The endpoint is named rk-cces-vpce-<id> and is IPv4-only and carries no endpoint policy. Private DNS is not enabled. The endpoint connects to the Rubrik endpoint service for your backup cluster.

    Rubrik places the endpoint in one subnet in each Availability Zone of the VPC where the Rubrik endpoint service is available. In each zone, Rubrik picks an available subnet that has at least one free IP address. The endpoint uses one private IP address from each selected subnet.

    The zones the endpoint covers are fixed when it is created. A host can be protected only if its Availability Zone has an endpoint network interface.

  • Security group: The security group is named rk-cces-vpce-sg-<id>, is attached only to the endpoint, and has no outbound rules. The security group allows inbound TCP traffic on ports 8011–8060 from your VPC's CIDR blocks (primary and secondary) so that protected hosts can reach Rubrik.

Both resources are tagged with rubrik:cces-baas = true and a Name tag. The <id> suffix identifies the Rubrik backup cluster. If hosts in one VPC are protected by more than one Rubrik backup cluster, the VPC contains one endpoint and security group pair for each cluster.

Rubrik creates the endpoint and security group when the first host in the VPC is onboarded. Every subsequent protected host in that VPC reuses them. Hosts in different VPCs get their own pair. The endpoint and security group remain in place for as long as Rubrik protects hosts in that VPC.

CAUTION:
Do not edit or delete the endpoint or its security group while hosts in the VPC are protected. If an inbound rule is removed, Rubrik restores it the next time a host in the VPC is onboarded. Do not create your own security group named rk-cces-vpce-sg-<id>. Onboarding cannot use a group with that name unless Rubrik creates it.

How Rubrik uses Systems Manager to install RBS

Rubrik creates one AWS Systems Manager (SSM) Command document named rubrik-cces-baas-onboard in each AWS account and region that contains protected hosts. The document holds all the scripts RSC runs on your hosts.

Rubrik creates the document once, and every protected host in that account and region reuses it. RSC updates the document only when Rubrik releases new versions of its content.

You can view the content of the SSM Command document from Systems Manager > Documents > Owned by me, or by running the aws ssm get-document --name rubrik-cces-baas-onboard command.

For each host you protect, RSC runs the rubrik-cces-baas-onboard document three times to perform the following operations in order:

  1. Detects the host architecture to verify that the host is supported.
  2. Generates a host key and certificate request.

    The host generates its own private key locally. The private key never leaves the host. The host returns only the certificate signing request, which contains the public key, to Rubrik. Rubrik signs it to establish the host's secure connection to its backup cluster.

  3. Installs the Rubrik Backup Service.

    The host downloads the installer package and its per-host configuration bundle from Amazon S3. Next, the host verifies each download's SHA-256 checksum before using it, and then installs and starts the service.

Every command appears in Systems Manager > Run Command > Command history and in AWS CloudTrail. The install command's parameters include signed download links. These links expire within minutes and cannot be used later.

Rubrik can run only its own rubrik-cces-baas-onboard document through this role. The role has no permission to run other SSM documents, including AWS-managed documents such as AWS-RunShellScript. Rubrik cannot run arbitrary commands on your instances.

If a host is not an online managed node when you tag it, RSC waits up to 30 minutes for it to come online, then reports a failure.

What the RBS installer does on the host

The RBS installer makes the following changes on the host:

  • Installs RBS, which includes the secure-connection client that links the host to its backup cluster.
  • Places the connection configuration and certificates under the RBS data directory, in conf\baas. The host generates its private key in %ProgramData%\Rubrik\baas\certs and moves it there during installation.
  • Restarts RBS, which then starts the secure connection to each node of the backup cluster.

The installer uses temporary files during installation and removes them after it finishes.

Removing protection

Removing protection from a host does not remove the associated Rubrik resources. The VPC endpoint, its security group, the SSM document, and RBS on the host remain in place.

Cost

  • Standard AWS charges for interface VPC endpoints apply to your AWS account. AWS charges hourly for each Availability Zone the endpoint covers, plus data processing.
  • Systems Manager Run Command and Command documents have no additional AWS charge.
