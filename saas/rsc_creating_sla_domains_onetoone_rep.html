Creating SLA Domains for one-to-one replication

Create an SLA Domain for one-to-one replication when there are more than two replication targets and the source and replication clusters are in a dedicated replication configuration. With one-to-one replication, you can configure multiple replication pairs, but a source cluster can replicate to a maximum of two target clusters.

Before you begin

Do the following:
  • Review the settings for the specific object types listed in Supported features for RSC workloads.
  • Select the workload types that support archiving and replication. One-to-one replication is supported only for data center workloads.
  • Create a replication pairing between the source and target clusters before creating the SLA Domain.
  • Enable quorum authorization if you plan to use the retention lock feature.

About this task

RSC displays options for custom SLA Domains based on the selected workload type, as each type has unique properties to protect its objects.

Procedure

  1. Log in to RSC.
  2. Click and select Data Protection.
    The Data Protection dashboard appears.
  3. On the navigation bar, click SLA Domains.
    The SLA Domains page appears.
  4. Click Create SLA Domain.
    Ensure that you understand the provided information about SLA Domains, including snapshot frequency and retention policies, before proceeding to create one.
    The Create SLA Domain wizard appears.
  5. Click Create on the Create SLA Domain page that describes SLA Domains.
    Selecting Do not show again skips this page the next time you create SLA Domains.
  6. Select the workload types and click Next.
  7. Optional: Turn on Retention Lock.
    OptionDescription
    Governance mode Requires quorum authorization.

    Governance mode retention lock appears by default and requires quorum authorization.
    Compliance mode

    Does not require quorum authorization.

    Selecting the mandatory acknowledgment enables you to proceed to the next step.

    To enable compliance mode retention lock, contact Rubrik Support.
  8. Click Next.
  9. Enter a snapshot frequency and a corresponding retention period.
    The snapshot frequency categories are optional, but at least one category must have a value.
  10. Optional: In Snapshot window, enter a time window for the snapshot.
    When you specify a snapshot window, RSC takes the snapshot during the specified time frame. Workloads managed by a Rubrik cluster use the timezone of that Rubrik cluster. Workloads managed by RSC use the UTC timezone.
  11. In First full snapshot, select a start type.
    OptionDescription
    First opportunity The first full backup occurs by default when a data source has been added.
    Custom range The first full backup occurs within a specified window.
  12. Click Next.
    The Archival and Replication page appears.
  13. Optional: Select Archival.
    Selecting this option configures archival locations for disaster recovery and long-term retention of data center workloads.

    Click Learn more to explore configuring archival locations for disaster recovery and long-term retention.

  14. Select Replication and choose One-to-one.
    Click Learn more to learn about setting up replication pairings between source and target clusters.
  15. Click Select Source Clusters to create a replication pairing.
    RSC displays clusters based on your view permissions, the presence of an archival location, and replication pairs. You can see clusters with replication targets or archival locations only when you have the required permissions.
  16. Click Save.
  17. On the Archival and Replication page, click Next.
    The Replication Parameters page appears.
  18. In Replication Policy 1, select the target clusters.
    You can select target clusters only if they are part of an existing replication pairing, are connected, and you have the necessary permissions to use them as replication targets.

    When no target cluster exists in the Select Target Cluster dropdown list, click Replication Pairings to create a replication pair.

  19. In Replication Retention, enter the number of days for which you want to retain the replicated snapshots.
    Alternatively, you can use the slider to adjust the retention period within the available range.

    You can add a maximum of two replication policies.

  20. Optional: Select Enable Cascading Archival.
    Selecting this option enables the target cluster to transfer replicated data to an archival location.

    Selecting Enable Cascading Archival requires choosing the archival locations for the cascading archival policy. The clusters are determined by what was selected in the replication step. You can add a maximum of two cascading archival policies.

  21. Click Next.
  22. Configure object type details based on the selected workloads and click Next.
    The Workload-specific settings for SLA Domains topic provides more details about the settings available for a specific workload.
  23. Click Next.
    The Confirmation page appears.
  24. In SLA Domain name, enter a name to identify the SLA Domain.
  25. Optional: In Add Description, enter a description to provide additional context for the SLA Domain.
  26. Review the configuration details and click Create.
    A message that the SLA Domain for one-to-one replication has been successfully created appears.

Results

RSC creates an SLA Domain for one-to-one replication for the selected workloads.
