Restoring Azure virtual machine using a snapshot

Use an Azure virtual machine snapshot to replace the original virtual machine with a fully functional point-in-time copy.

About this task

RSC creates copies of the managed disks from the snapshot and replaces them on the virtual machine (VM). This restores the VM to its original version when the snapshot was taken.

RSC does not support restoring Generalized Azure VMs as it requires powering off the VM and replacing the operating system disk. Generalizing an Azure VM removes machine-specific information so that the image can be used to create multiple VMs. Hence, the Azure platform does not allow the restart of a generalized VM.

If a shared disk is attached to the VM being restored, RSC detaches the shared disk from the VM and recovers the VM with a new copy of the shared disk. After the restore operation is complete, the shared disk continues to be attached to all VMs it was originally attached with, except the restored VM.

Procedure

  1. Log in to RSC.
  2. Click and select Data Protection.
    The Data Protection dashboard appears.
  3. On the navigation bar, click Inventory.
    The Inventory page appears.
  4. Click the Azure - VMs & Applications inventory card.
    The Azure Virtual Machines page appears.
  5. Click the VM name that you want to restore.
    The VM details page appears.
  6. In the calendar view, click the date of the snapshot.
  7. Hover over for a snapshot and click Recover.
    The Azure VM Recovery wizard appears.
  8. Select Restore and click Next.
    The Virtual machine details page appears.

    If the subscription does not have the Export and Restore permission category assigned, a message appears indicating that you must assign the required permission category. In this case, you can click Assign Permission to assign the permission category to the selected subscription.

  9. Optional: Select Restore Tags.
    RSC reverts the labels on the restored VM and any attached managed disks to their state at the time of the backup.

    If not selected, the tags on the VM are not modified. The restored disks have only the Rubrik metadata tags.

  10. Optional: Select Launch in powered off state.
    The restored VM is launched with the power off.
  11. In Recover from, select the snapshot to restore if multiple copies of the backup exist.
    • Original copy
    • Replicated copy (Replication enabled)
    • Archived copy (Archiving enabled)
    On the Recovery option page, if the original copy of the snapshot has expired, the Recover from list displays only the replicated and archived copies. When multiple archival locations are configured in the associated SLA Domain, multiple archival copies are available for selection.
  12. Click Next.
    The Select disks page appears, with all the disks selected by default.
  13. Clear the disks that you do not want to recover.
    The operating system disk is selected by default and cannot be cleared.
  14. Click Recover.

Results

RSC restores the VM to a fully functional point-in-time copy.
