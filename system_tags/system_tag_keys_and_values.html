System Tag keys and values

System Tags support an optional key paired with a required value, enabling you to more precisely categorize and filter data assets in RSC.

This topic describes a feature or features that Rubrik is gradually rolling out to customers.

Overview

Every System Tag has a required value and can optionally include a key that provides domain context for the value. For example, you can create tags such as region:america or env:prod to make your metadata more precise and easier to filter.

Tags with a key and tags without key can coexist in the same workspace. For example, a value-only tag, america, and a tag with a key, region:america, are treated as distinct tags.

Note:
RSC does not support assigning objects from a disconnected Rubrik cluster. You can assign only objects that RSC supports for System Tags.

Tag identity and uniqueness

A tag's identity is the combination of its key, if present, and its value within your workspace. The following tags are all unique and can coexist:

  • america (value-only, no key)
  • region:america
  • market:america

Tag keys and values are not case-sensitive when checked for uniqueness, but they display in their original case. For example, Region:America and region:america are treated as the same tag.

Filtering and search

You can filter your inventory and search for objects using tag keys and values in RSC. You can filter by key only, by value only, or by a specific key and value combination.

Validation rules

When creating a System Tag, the key and value must meet the following requirements:

  • Keys and values can contain letters, numbers, dashes, and underscores.
  • Keys can be up to 64 characters. Values can be up to 128 characters.
  • Values are required. Keys are optional.
