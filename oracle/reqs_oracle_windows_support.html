Oracle support requirements on Windows

Requirements for protecting Oracle databases on Windows with RSC.

The following table describes the support requirements for using RSC to protect Oracle databases on Windows.
Support requirement Description
Windows operating system Windows server versions 2016, 2019, and 2022.
sqlnet.ora configuration
Set the SQLNET.AUTHENTICATION_SERVICES parameter in the sqlnet.ora file to specify NT native authentication:
SQLNET.AUTHENTICATION_SERVICES = (NTS)

NTS authentication connects to an Oracle database using operating system-level authentication.
Windows ports To add the Oracle host on a Windows system, you must configure inbound and outbound firewall rules for ports 12800 and 12801. If you do not add these inbound and outbound rules, RSC displays a message indicating that the connection to RBS timed out.
Rubrik cluster ports Oracle on Windows requires that all Rubrik cluster nodes have port 9639 open.
Oracle version Oracle versions 12.1, 12.2, and 19c.

Due to an Oracle limitation, Oracle Database 12.1 on Windows does not support PDBs.
Data transfer The connection between the OracleBackupAssistant and the Rubrik cluster uses Dokan for data transfer. RSC installs the Dokan driver on the Windows host during the first backup or recovery job. All workflows, including Live Mount and Instant Recovery, use secure thrift as the data transfer mechanism on Windows.
Rubrik software Rubrik CDM versions 9.2 and later.
Rubrik Backup Service (RBS) user The RBS user account is used for all discovery, backup, and recovery workflows. This account must have permission to connect to the database. RSC does not support switching the RBS user account after installation. The account must have local administrator group privileges on the Windows host.
SYSDBA user

A Windows user account in the administrators group is required for installation on the Windows host.

A Windows user account with SYSDBA privileges to the ora_dba group is required on the Windows host to ensure that RBS can authenticate with the Oracle instance and perform refresh and backup tasks. The SYSDBA privilege enables the user account to log in to the database by using the CONNECT AS SYSDBA command without a password prompt. The SYSDBA user can then run queries and scripts.
