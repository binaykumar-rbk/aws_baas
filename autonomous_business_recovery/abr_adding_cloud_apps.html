Adding a cloud application for Autonomous Business Recovery

Add a cloud application in RSC by specifying application details, defining the application objects by tag, by manual selection, or both, and reviewing the discovered resources.

Before you begin

Ensure that you complete the following tasks in sequence:
  • Add the source and recovery AWS cloud accounts to RSC with the required permissions:
    • For the source account, enable the Basic permission category of the Cloud Applications feature. For more information, see AWS cloud account addition for Autonomous Business Recovery.
    • For the recovery account, enable both the Basic and Recovery permission categories of the Cloud Applications feature. For more information, see Adding a recovery account for Autonomous Business Recovery.
  • Plan the cloud application boundary: Decide upfront which single AWS account and single AWS region will host the application. Everything that follows depends on this choice because, although a cloud application can span multiple accounts or regions, RSC can only protect resources within a single account and region and can only recover them to the same region in the recovery account.

    Ensure that the AWS resources forming the cloud application that needs protection are within a single AWS account and a single AWS region. Confirm the following in the AWS Management Console:

    • AWS account ID. The signed-in account appears in the top-right of the AWS Management Console. You can also run aws sts get-caller-identity from the AWS CLI, or inspect any resource ARN, which embeds the account ID. For more information, see Using an alias for your AWS account ID (AWS documentation).
    • AWS region. The region selector appears in the top-right of the AWS Management Console. The EC2, RDS, and VPC pages only list resources in the currently selected region. For more information, see AWS Documentation for Regions and Zones.
    • Verify the scope across regions. Use AWS Resource Explorer or AWS Tag Editor to search for the tags of the application across all regions in the account. If results return from more than one region, the resources span multiple regions and cannot form a single cloud application. For more information, see What is AWS Resource Explorer?, Searching for resources, and Find resources to tag.
  • Optional: Tag AWS resources in the AWS Management Console. Apply consistent tag keys and values to EC2 instances, RDS databases, and load balancers that belong to the application. RSC uses these tags to select objects and then runs auto-discovery to identify all connected configuration resources. If you do not tag resources, you can select objects manually in the wizard. For more information, see Tag-based resource discovery for cloud applications.

About this task

A cloud application is a logical grouping of AWS resources within a single region. You define the application by specifying up to three tags, by selecting objects manually, or by using both. RSC discovers the related workloads and connected configuration resources automatically.

Procedure

  1. Log in to RSC.
  2. Click and select Data Protection.
    The Data Protection dashboard appears.
  3. On the navigation bar, click Inventory.
    The Inventory page appears.
  4. Do one of the following:
    ChoiceDescription
    Setting up a cloud application for the first time
    Do the following:
    1. Click Add Workload.
    2. Click Cloud Applications.

      The Add Workload page appears.

    3. Click Set up.

      The Protect Your Cloud Applications page appears.

    4. Review the Before you get started section that indicates the prerequisites to tag your cloud objects with consistent tag keys and tag values, if you plan to use tags, and set up your recovery account in RSC.
    5. Click Add Cloud Application.

      The Add Application wizard appears.
    Already added a cloud application and want to add another one
    Do the following:
    1. Click the Cloud Applications inventory card.

      The Cloud Applications inventory page appears.

    2. Click Add Application.

      The Before you get started page appears.

    3. Review the Before you get started section that indicates the prerequisites to tag your cloud objects with consistent tag keys and tag values, if you plan to use tags, and set up your recovery account in RSC.
    4. Click Get Started.

      The Add Application wizard appears.
  5. In Application Details, enter the application name.
  6. Select the Cloud Account and Region for the application.

    A cloud application is scoped to a single AWS account and region. All resources in the application must reside in the selected region.

    You can only recover the application to the same region. For example, if you select US West 2 as the source region, recovery is limited to US West 2 in the recovery account. RSC does not support cross-region recovery.

  7. In Recovery Location Details, select the Recovery Account for application recovery.

    You must provide a recovery account at the time of application creation. During each backup, RSC replicates resources such as AMI snapshots from the source account to the recovery account. This pre-replication process enables faster recovery without requiring access to the source account during the actual recovery process.

    Pre-replicating resources to the recovery account is important because the typical use case for application recovery is when the source account is compromised. During recovery, RSC does not access the source account, which is why you must configure the recovery account beforehand.

    The Recovery Region appears. The recovery region is automatically set to the same region as the source account.
  8. Click Next.
  9. Define the objects that belong to the application.
    The page that appears depends on your account. If the account has too many objects to select manually, RSC displays the tag-based page.
    Page that appearsSteps
    Select App Objects

    The left pane groups the resources in your AWS account into Networking, Compute, Containers, Storage, Database & Caching, and Security & Identity. Each group lists its object types with the number of selected objects, for example Load Balancer 0/5.

    Do the following:
    1. To preselect objects by tag, click Add Tags adjacent to Select via tags, select a tag key and value for each tag, and then click Save.

      You can specify up to three tags. RSC selects the objects that match the tags, and the Selection column shows Tagged for them. To change the tags, click Edit Tags.

    2. Expand an object type, and select or clear objects as needed.

      Each row shows the object name, its ARN, how it was selected, and its dependent objects. To find an object, search by object name or ARN.

    3. Review the dependent objects.

      After each selection change, RSC identifies the objects that the selection depends on, for example the VPC, subnets, and security groups of an EC2 instance, and adds them to the application. The Dependent Objects column shows how many of these objects are selected, for example 10/10 selected. You can clear optional dependent objects. You cannot clear an object that is coupled with a selected object, for example the VPC that an EC2 instance requires.

    4. Click Next.

      The Review page appears with the app objects listed by object type.

    The Selection column shows how each object was selected: Tagged, Manually included, Auto-included, or Excluded.
    Add Tags to Define Application Objects

    The page shows the number of objects that RSC discovered in the selected account and region.

    Do the following:
    1. Click Add Tags.
    2. Select tag key and value for each tag from the pre-retrieved list from AWS cloud to identify the resources belonging to the application.

      You can specify up to three tags. At this point, the application is a construct only. RSC uses the tags you specify to discover EC2 instances, RDS databases, and load balancers that belong to the application, and then auto-discovers all connected configuration resources. For more information, see Tag-based resource discovery for cloud applications.

    3. Click Save.

      RSC discovers the resources that match the specified tags.

    4. Review the discovered resources.

      The Application Tags page lists your tags and a table of object types with the number of tag-matched objects for each type, such as Load Balancers, EC2 Instances, Lambda, RDS Databases, ElastiCache, S3 Buckets, EKS, and ECR. The counts reflect tag-matched objects only. For load balancers, the count is shown as Discovered Later. A summary shows the number of objects added to your application. Select an object type to review the discovered objects. To change the tags, click Edit Tags.

    In addition to the objects that you tag or select, a background sync job runs to discover connected resources that are not directly tagged. This auto-discovery process searches the complete resource dependency graph to identify all resources that must be a part of the application, such as subnets, auto-scaling groups, launch templates, option groups, and subnet groups. You do not have to tag each resource in the application. For more information, see Tag-based resource discovery for cloud applications.

  10. Click Save to create the cloud application.

Results

RSC creates the cloud application and a background sync job starts to build the complete application by discovering all connected resources. After the sync completes, the application appears in the Cloud Applications inventory. On the Resources tab, workloads and configuration resources are listed separately by type, including AWS Configurations, VPCs, load balancers, EC2 instances, RDS databases, IAM roles, and Route 53 hosted zones. You can now assign SLA Domains to protect the cloud application.
