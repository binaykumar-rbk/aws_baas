Recovery point selection for AWS cloud application

Information about the recovery point selection options available when recovering an AWS cloud application in RSC.

Snapshot Selection page

The Snapshot Selection page in the recovery wizard displays all objects in the application, including AWS configuration resources, EC2 Instances, and RDS Databases, with their selected snapshots and snapshot locations. You can refine the recovery point selection using three controls: Select latest, Snapshots taken before, and From location.

Snapshot selection options

The following table describes the options available on the Snapshot Selection page.

Option Description
Select latest

You choose the snapshot filter from the list. These filters are based on the Rubrik Data Threat Analytics (DTA) that runs in the backend to identify anomalous or quarantined snapshots for EC2 and RDS snapshots only. The following options are available:

  • Non-quarantined and non-anomalous (default): Selects the most recent clean snapshot per workload with no detected anomalies and no quarantine flag. You can use this option for actual disaster recovery scenarios where you want to recover from a known clean recovery point.
  • Quarantined: Selects only quarantined snapshots. You can use this option when you want to investigate a snapshot that was flagged and verify whether the application works correctly from that snapshot.
  • Anomalous: Selects only snapshots flagged as anomalous. You can use this option when you want to recover from a snapshot that was flagged as anomalous to validate whether the application is affected.
  • Don't consider: Selects the most recent snapshot regardless of quarantine or anomaly status. You can use this option when you do not want to filter based on threat monitoring data and want the latest available snapshot.
Note:
These filters require the Rubrik Data Threat Analytics (DTA) feature to be enabled in your account. If threat monitoring is not enabled, all snapshots are considered as non-quarantined and non-anomalous by default. For more information on enabling Threat Monitoring, see Enabling Threat Monitoring.
Snapshots taken before You specify a date and time to filter snapshots. RSC selects the latest snapshot at or before the specified timestamp for every workload and the matching configuration snapshot. You can use this option for cyber-recovery scenarios where you know the exact target timestamp.
From location

You select the snapshot location for EC2, RDS, and S3 snapshots from the drop-down list. The following options are available:

  • Any Location: Selects snapshots from any available location.
  • Primary Locations: Selects snapshots from the primary storage location.
  • Replication Locations: Selects snapshots from a replication target. RSC does not support RDS recovery from the replicated snapshot.
  • Archival Locations: Selects snapshots from an archival location. Recovery falls through to the next fastest source if the preferred source associated to the workload has no snapshot.

Best practices

  • For cyber-recovery scenarios, Rubrik recommends using the Snapshots taken before option to recover to a known clean timestamp.
  • Rubrik recommends reviewing the selected snapshot for each object before proceeding to ensure that all workloads have a valid snapshot selected.
  • Rubrik recommends selecting a recovery point that aligns with the Recovery Point Objective (RPO) of the application to minimize data loss.
