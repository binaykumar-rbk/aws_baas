Supported resource types for AWS cloud applications

Information about the AWS resource types that RSC supports for cloud application protection and recovery.

Workload resources

RSC takes snapshots of workload resources to protect their data. Each workload has its own SLA Domain for protection. The SLA Domain associated with the cloud application does not govern these backups.

Resource type Description
EC2 instances EC2 instances and all attached EBS volumes. RSC creates AMIs for backup and replicates them to the recovery account. Instances that an Auto Scaling group manages are not backed up as workloads. RSC protects the launch template instead.
Note:
Standalone EBS volumes, also referred to as EBS workloads, are not in scope for this feature. Only EBS volumes attached to EC2 instances are protected as part of the EC2 backup.
RDS databases RDS Database instances. RSC takes native engine snapshots for backup.
Aurora databases Aurora DB clusters. RSC takes native cluster snapshots for backup.
S3 buckets S3 buckets and their objects. You can recover a bucket to a new bucket or to an existing bucket, and use prioritized recovery to recover specific files first or only. For more information, see Recovering an AWS cloud application to a recovery account.

Configuration resources

Configuration resources are the configuration-only AWS resources that surround the workloads and that the workloads depend on, such as VPCs, subnets, security groups, IAM roles, load balancers, Lambda functions, EKS and ECS clusters, ElastiCache, ECR repositories, and Secrets Manager secrets. RSC captures metadata for these resources and stores it in a secure Rubrik-managed cloud storage bucket. The following resource types need an additional backup mechanism for their payloads: AMIs and EBS snapshots that launch templates reference and ECR images are replicated to the recovery account, and Lambda code, Lambda layers, and Secrets Manager secret values are stored in the backup location of the SLA Domain.

Note:
IPv6 and all IPv6-related settings are not supported. Cloud applications that use IPv6 networking cannot be protected or recovered using this feature.

  • Launch Templates that reference an AMI through an AWS Systems Manager (SSM) parameter are not recovered.

KMS aliases Aliases associated with KMS keys.
IAM policies AWS Identity and Access Management (IAM) policies associated with the cloud application resources.
IAM roles AWS IAM roles associated with the cloud application resources.
Networking Route 53 hosted zones DNS hosted zones that manage DNS records for your application.
Elastic IPs Static IPv4 addresses allocated for use with AWS resources.
Containers Lambda functions AWS Lambda functions. Backing up Lambda functions requires a backup location in the SLA Domain. For more information, see Creating an SLA Domain for AWS cloud applications.
EKS Amazon Elastic Kubernetes Service (EKS) resources associated with the application. RSC backs up only the cluster configuration metadata. It does not back up application data or the Kubernetes objects inside the cluster.
ECR repositories Amazon Elastic Container Registry (ECR) repositories associated with the application. RSC replicates only the images that you push after it applies the replication policy.
Secrets Secrets Manager secrets AWS Secrets Manager secrets. Backing up secrets requires a backup location in the SLA Domain. RSC supports up to 1,000 secrets for each cloud application. For more information, see Creating an SLA Domain for AWS cloud applications.

ECS ECS clusters Amazon Elastic Container Service (ECS) clusters associated with the application.
ECS task definitions ECS task definitions associated with the application.
Note:
The following VPC-related resource types are not supported and are not backed up or recovered: Route Server. Route Server resources are discovered as part of application inventory but cannot be protected or restored using this feature.
