Autonomous Business Recovery limitations

Information about the known limitations that apply to Autonomous Business Recovery for Cloud Applications, that is, protection and recovery of AWS cloud application with RSC.

Limitation Description
Single-region boundary A cloud application is limited to a single AWS account and a single AWS region. Discovery, configuration backup, and protection-status calculation are all scoped to one source account and region. RSC does not support multi-account, multi-region, and multi-cloud applications.
Cross-account, same-region recovery only The recovery destination must be a different AWS account in the same AWS region as the source AWS cloud account. RSC does not support cross-region recovery.
Recovery target account change Changing the recovery target account between backup and recovery is risky. Replicated resources, such as AMIs and EBS snapshots, are copied at the time of backup into whichever target account was configured then. If you change the target account and initiate recovery before the next successful application snapshot, those replicated resources will not be in the new target account and recovery of the same account will fail. You must always wait for at least one full application snapshot cycle after changing the target account.
Tag limit You can specify up to three tags for each cloud application for resource discovery. A resource that matches at least one of the tags is added to the application, because the tags are combined by using OR. You can also select resources manually.
Supported resource types In-scope resource types are limited to the supported workload types and configuration types listed in Supported resource types for AWS cloud applications.
Cloud application SLA Domain cannot inherit The cloud application SLA Domain can only be applied directly to an application. It does not inherit from parent objects such as the account or region, and does not flow into individual workloads.
Minimum backup frequency for cloud application SLA Domain The minimum backup frequency for cloud application SLA Domains is 6 hours. RSC rejects any backup frequency set below 6 hours, including sub-6-hour hourly schedules and all minute-level schedules.
Workload SLA Domain compliance Workload SLA Domains must be at least as strict as the cloud application SLA Domain for the application to achieve Fully Protected status.
Recovery idempotency and lock recovery Recovery is best-effort idempotent. Re-running a recovery will not duplicate resources it already created, but this is best-effort and not guaranteed. After locking, you cannot automatically clean up the recovered resources using RSC. The lock recovery action is permanent and irreversible.
Workload snapshot support Only workload snapshots, such as EC2 instances, RDS databases, and Aurora DB clusters, created after the Cloud Application feature is enabled are fully supported for recovery. Snapshots taken before the Cloud Application feature enablement may not recover completely and can cause recovery failures, because the required configuration metadata were not captured at backup time.
RDS archived snapshot recovery Recovery from an RDS archived snapshot has limited support. If you use the Clone the source VPCs network option, RSC sets up the connectivity between Exocompute and the recovered RDS database, and you must add the RECOVER RDS CONNECTIVITY permission group to the Exocompute account. If you select the Use already created VPCs from the recovery account option, recovery is supported only when the target VPC already exists in the recovery account and network connectivity has been configured. If these prerequisites are not met, recovery from an RDS archived snapshot is not supported. For more information about the inbound rule for RDS PostgreSQL database recovery, see Network rules for EKS node at VPC or firewall.
On-demand backup You can take an on-demand snapshot of only the AWS configuration resources of a cloud application. For on-demand snapshot of individual workloads, such as EC2 instances, RDS databases, or S3 buckets, you must initiate it directly from the inventory page for that specific workload. You can initiate an on-demand inventory refresh, but a refresh only re-discovers resources and does not take a snapshot. For more information, see Taking an on-demand AWS configuration snapshot of a cloud application.
Maximum co-enabled features A maximum of four other Rubrik features can be enabled on the same AWS cloud account alongside Cloud Applications. This limitation applies to each AWS account onboarded on RSC, until the multi-role feature is enabled.
Recovery from replicated RDS snapshot Recovery from a replicated RDS snapshot is not supported.
DHCP options DHCP options are not created during recovery. The recovered VPC will use the default DHCP options in the recovery account.
IAM permission boundaries IAM permission boundaries are not supported. IAM roles are recovered without any permission boundaries that were applied in the source account.
Transit Gateways Transit Gateways and their attachments are not supported. Transit Gateway VPC attachments are discovered as part of application inventory but are not backed up or recreated during recovery.
VPC endpoint policy changes VPC endpoint policy changes are not supported. VPC endpoints and their endpoint policies are restored exactly as they were configured in the source account. No modifications are made to the endpoint policies during recovery.
Route Server Route Server is not supported. Route Server resources are not backed up or recovered.
OIDC authentication on Load Balancers OIDC authentication on load balancers is not supported. Load balancers using OIDC-based authentication are recovered without the OIDC configuration.
Launch Templates referencing AMI through SSM parameter Launch Templates that reference an AMI through an AWS Systems Manager (SSM) parameter are not recovered. The recovery requires a direct AMI reference in the launch template.
Route table targets Only the following route targets are restored during recovery: Internet Gateway, Local, NAT Gateway, Network Interface, VPC Peering, and VPC endpoints. Any other route target type is not supported and is not restored.
IPv6 IPv6 and all IPv6-related settings are not supported. Cloud applications using IPv6 networking cannot be protected or recovered using this feature.
RDS DB Proxy RDS DB Proxy is not supported. RDS DB Proxy resources associated with the application are not backed up or recovered.
Carrier Gateway routes Carrier Gateway routes are not supported and are not restored during recovery.
Capacity Reservation for recovered EC2 instances Launching recovered EC2 instances into a Capacity Reservation is not supported.
Supported platform AWS cloud applications are supported only on RSC.
Backup location The backup location for Lambda functions and Secrets Manager secrets is always an S3 bucket.
You can use either of the following:
  • A customer-managed S3 bucket
  • A Rubrik Cloud Vault (RCV) location. For backup and recovery, RSC supports only the RCV-R tier.
The backup location supports only Server-side Encryption (SSE). Client-side Encryption (CSE) is not supported.
Existing images in ECR repositories The AWS replication policy replicates only the images that you push after the replication rule is created. Images that already exist in the repository are not replicated to the recovery account.
Standalone EBS volumes Standalone EBS volumes, also referred to as EBS workloads, are not supported. Only EBS volumes attached to EC2 instances are protected as part of the EC2 backup.
Classic and Gateway Load Balancers RSC does not support Classic and Gateway Load Balancers. RSC supports only Application Load Balancers and Network Load Balancers for protection and recovery.
