Claude connections overview

You can connect Claude Code, Claude Cowork, and Claude chat to Agent Cloud for session visibility and real-time enforcement.

No single Agent Cloud connection covers every place Claude runs. Setup has two parts: session ingestion, which brings Claude activity into Agent Cloud for monitoring and policy evaluation, and hooks, which enforce Block and Ask policies on prompts and tool calls. The right method for each depends on the Claude product and plan.

Before you deploy

Wherever Agent Cloud ingests sessions, you get alerts for policies set to Monitor. Monitor policies work as long as Agent Cloud has the sessions. Hooks are required only for policies set to Block or Ask.

Important:
Use only one blocking method for each device, either an AI gateway or endpoint hooks configured through Claude Code managed settings. If an AI gateway routes Claude Code traffic from the device, use the gateway for blocking. Otherwise, use endpoint hooks.

The following limits apply to these connections:

  • A device that has both the endpoint hooks and the Rubrik hooks plugin reports each prompt and tool call twice. Use one or the other on each device.
  • Real-time blocking fails open. If Agent Cloud is unreachable when a hook fires, Claude proceeds without enforcement.
  • Hooks evaluate user prompts and tool calls. They do not evaluate responses from the model.
  • Endpoint detection reports activity from any Claude account signed in on a managed device, including personal Pro, Max, and Ultra accounts. It does not block the sign-in itself.
  • The Claude Enterprise connection reads chat history. It cannot block activity.
  • The browser extension detects visits to Claude. It does not capture prompts or evaluate Agent Cloud policies on them.

Recommended setup by Claude product

Team plans do not support the Claude Compliance API. Pro, Max, and Ultra plans have no organization admin settings, so they cannot use the Compliance API, OpenTelemetry monitoring, or organization plugins.

The following table describes the recommended session ingestion and hook setup for each Claude product.

Claude Code on the command line and in the desktop app

Runs on the user device.

Enterprise, Team, Pro, Max, and Ultra: Endpoint detection through mobile device management (MDM).

  1. Create an MDM connection in Agent Cloud and copy the endpoint URL and API key.
  2. Deploy the Rubrik endpoint detection binary to your managed macOS, Windows, and Linux devices with your MDM solution, such as Jamf Pro or Microsoft Intune, and run it at the frequency you want, for example once a day.
Note:
If you are not the MDM administrator for your organization, you can run the binary yourself to test on one machine, once or on a schedule such as a cron job. For the install and scheduling steps, see Installing the endpoint detection binary on macOS, Installing the endpoint detection binary on Linux, and Installing the endpoint detection binary on Windows. For more information about running the binary and checking that sessions were ingested, see Verifying endpoint session ingestion.

Enterprise, Team, Pro, Max, and Ultra: Endpoint hooks.

No separate setup. Each run of the endpoint detection binary installs Claude Code managed settings that call Agent Cloud on every prompt and tool call. A policy set to Block enforces it.

Claude Cowork (local)

Runs on the user device, in the Claude Desktop app, with Cowork in the cloud turned off.

Enterprise and Team: Endpoint detection through MDM, using the same steps as Claude Code.

The binary collects Cowork sessions from the Claude Desktop app. Linux has no Claude Desktop build.

Pro, Max, and Ultra: Not applicable. Cowork on these plans runs only in the cloud.

Enterprise and Team: Endpoint hooks, installed by the same binary as Claude Code.

Claude Code and Claude Cowork share one hook endpoint, so Agent Cloud treats them as one agent family. A policy that names one applies to both.

Pro, Max, and Ultra: Not applicable. Cowork does not run locally on these plans.

Claude Cowork (cloud)

Runs in Anthropic cloud. Depending on your plan and organization settings, new Cowork tasks run in the cloud by default.

Enterprise and Team: OpenTelemetry, because the Compliance API does not provide standalone cloud Cowork sessions and MDM cannot see them.

  1. In Agent Cloud, create an OpenTelemetry connection. Copy the endpoint URL and the bearer token. The endpoint URL looks like https://webhooks.<domain>/<id>/<id>/v1/otlp.
  2. In Claude, select Data and privacy > Monitoring. In OTLP endpoint, enter the endpoint URL. In OTLP headers, enter the bearer token as the authorization header. Set OTLP protocol to http/json.
  3. Turn on content capture by setting otlpContentCapture on your managed devices. Without it, sessions contain metadata only. For more information, see Configuring content capture for Claude Desktop.
  4. In Agent Cloud, click Runtime, and then select Sessions from the dropdown to confirm that Claude Cowork sessions arrive.

Pro, Max, and Ultra: Not supported. The Monitoring form is an organization setting that individual plans do not have.

Enterprise and Team: Rubrik hooks plugin. Managed settings do not apply to cloud sessions, so hooks must come from a plugin.

  1. Copy the endpoint URL and API key of the MDM connection that the plugin reports to. The endpoint URL looks like https://webhooks.<domain>/<id>/<id>/v1. Copy it exactly as the connection wizard shows it.

  2. Generate the plugin with the Rubrik endpoint detection binary, versions 0.9.3.1 and later, where <output-path> is the zip file directory.

    API_KEY=<YOUR_API_KEY> <path-to-binary> \
  -endpoint <YOUR_ENDPOINT_URL> \
  -create-claude-plugin <output-path>/rubrik-agent-cloud.zip

    The directory must already exist. The command writes the zip file, replaces any existing file at that path, and exits.

    Important:
    The zip file contains the API key in cleartext and is readable only by its owner, so treat it as a secret.

    The plugin scripts require Python 3, which Anthropic cloud includes.

  3. In Claude, select Organization settings > Plugins & skills. Add the plugin, and set its default access to Required. Cowork and Skills must both be turned on for the organization.
  4. In Organization settings, select Capabilities > Code execution. Turn on Allow network egress and add the domain of your Agent Cloud endpoint, such as webhooks.<domain>. Enter only the domain, with no https:// and nothing after it. The endpoint must be publicly reachable.
  5. In the Claude Code server-managed settings, remove allowManagedHooksOnly and disableAllHooks if they are set.

Pro, Max, and Ultra: Not supported. Organization plugins are an admin feature that individual plans do not have.

Claude Code on the web

Runs in Anthropic cloud.

 All plans: Not supported. The Compliance API excludes Claude Code on the web, and MDM cannot see activity that does not run on the device. All plans: Not supported. Managed settings installed on a device do not reach cloud sessions. Claude Code on managed devices is the alternative.

Claude chat on claude.ai and in Claude Desktop

Runs in Anthropic cloud, accessed through a browser or the desktop app.

Enterprise: The Claude Enterprise connection in Agent Cloud, which reads chat activity through the Claude Compliance API. The Claude Primary Owner creates the Compliance API key. For more information, see Deploying Claude Enterprise in Agent Cloud.

Team, Pro, Max, and Ultra: These plans do not provide the Compliance API, so Agent Cloud cannot ingest chat content. With the browser extension deployed, Agent Cloud shows visits to claude.ai.

All plans: Not supported for prompts. Claude ignores plugin hooks in chat.

To control access, deploy the browser extension and mark Claude as Unauthorized with the No unauthorized agents policy set to Block. This blocks visits to the site, not individual prompts.

Unified Claude experience, with chat and Cowork in one conversation

Runs in Anthropic cloud. A chat moves into a Cowork cloud session and back.

Available on Enterprise, Team, Pro, Max, and Ultra plans. On Pro, Max, and Ultra, it might not appear for every account. On Enterprise, an owner turns it on in Organization settings under Capabilities, with the Chat and Cowork unified setting. As of November 16, 2026, it is on by default if no administrator has turned it on or off for the organization. For more information, see the Anthropic documentation: Set up and manage the new unified Claude experience for your enterprise organization.

Enterprise: Both methods apply. The Compliance API covers the full conversation. OpenTelemetry covers the Cowork cloud portion, with metadata only. The steps for each method apply.

Team: OpenTelemetry covers only the Cowork portion, with metadata only. Agent Cloud cannot see the chat portion.

Pro, Max, and Ultra: The unified experience is available, but Agent Cloud cannot ingest it. With the browser extension deployed, Agent Cloud shows visits to claude.ai.

Enterprise and Team: Rubrik hooks plugin, as for Claude Cowork (cloud).

Plugin hooks run only in the Cowork portion of the conversation. They do not run in the chat portion.

Pro, Max, and Ultra: Not supported.

Claude through a third-party provider (3P), such as Amazon Bedrock

Claude is accessed only through your cloud provider, with no Anthropic plan and no Anthropic organization settings. Claude Desktop runs on the user device, and Chat, Cowork, and Code all run locally with no sessions in the Anthropic cloud.

Endpoint detection through MDM, using the same steps as Claude Code. The endpoint binary must be version 0.9.3 or later to collect Cowork sessions from Claude Desktop on 3P.

3P does not provide the Compliance API. Endpoint detection does not collect plain chat sessions.

 Endpoint hooks, installed by the same binary as Claude Code.

Agents you build with the Claude API or Anthropic SDK

Runs on your infrastructure. Does not depend on a Claude plan.

 OpenTelemetry, using the Anthropic SDK instrumentation. For more information, see Configuring an Anthropic SDK agent with OpenTelemetry. AI gateway, either a Rubrik-managed gateway or LiteLLM. The gateway uses the complete conversation history to block risky tool calls.
Note:
Session ingestion and hooks are independent. For example, a device can ingest Claude Cowork (cloud) sessions through OpenTelemetry and enforce policies through the Rubrik hooks plugin.

Content capture values for Claude Cowork

The otlpContentCapture setting controls which content Claude Desktop sends to Agent Cloud through OpenTelemetry. Without it, sessions contain metadata only.

The following table describes the otlpContentCapture values.
Value What it sends
userPrompts What users enter, plus responses from Claude
toolDetails Tool inputs, such as a web search query
toolContent Tool outputs, such as fetched page text or command output
Important:
Claude Desktop sends this content to the collector without redaction, so your security or privacy team needs to approve content capture before you turn it on.

The following limits apply to content capture:

  • Content capture applies only to Cowork sessions that users start from Claude Desktop, whether the session runs locally or in the cloud. Sessions that users start on the web or on mobile carry metadata only.
  • The Claude interface does not provide an otlpContentCapture setting. You set it on your managed devices.
  • Content capture does not apply to cloud scheduled tasks or to chats that Claude moves into the cloud when Chat and Cowork are unified.
  • The collector settings do not apply to Code tab sessions.
  • Cloud Cowork monitoring requires Claude Desktop version 1.22209.3 or later. Local Cowork monitoring requires version 1.1.4173 or later.
  • Some older versions of Claude Desktop send content when otlpContentCapture is not set. Update Claude Desktop on your devices to get metadata-only sessions by default.
