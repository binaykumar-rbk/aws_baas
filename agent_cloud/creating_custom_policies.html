        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

        • How policies work

          A policy is a named rule with a severity that Agent Cloud evaluates against your agents, tools, and sessions. When agent activity breaks a policy, Agent Cloud records a violation or an alert and, depending on the policy's enforcement mode, can stop the action.

        • Enforcement modes

          The enforcement mode of a policy determines what happens when agent activity breaks it: Monitor records an alert, Block stops the action before it runs, and Ask hands the action to the approval prompt of the agent.

        • Blocking support by connection

          Which items Agent Cloud can block, and whether Ask is supported, depends on the connection. Check this table before you set a policy to Block.

        • Agent Cloud system policies

          Agent Cloud includes multiple system policies. These policies are not enabled by default. You can enable them from the Policies page.

        • Agent Cloud policy packs

          Agent Cloud policy packs are curated collections of system policies you can add to your Agent Cloud account to enable a focused set of controls for a specific risk area, compliance framework, or industry.

Creating custom policies using an AI judge

Create a custom policy using an AI judge in Agent Cloud to control which tools, models, and actions AI agents in your environment can use.

About this task

Custom policies you create with an AI judge define the rules that Agent Cloud enforces against the AI agents, tools, and models in your environment. Each policy has a name, an enforcement type, a severity, and one or more rules that describe the behavior to allow, deny, or monitor.

Procedure

  1. Log in to RSC.
  2. Click and select Agent Cloud.
    The Agent Cloud page appears.
  3. Click Policies.
    Agent Cloud displays the Policies page, which contains a list of the policies configured in Agent Cloud.
  4. Click Create Policy.
    Agent Cloud displays the Create Policy wizard.
  5. In the text box, describe in natural language the policy to enforce.
    Agent Cloud enforces only policies that include tool calls. These policies can restrict which tools an AI agent can use and what content or actions the AI agent can perform as part of these tool calls.
    Agent Cloud translates the natural language description into a policy to enforce.
  6. Click Next.
    Agent Cloud displays the Review and Edit Policy page.
  7. Review the policy.
    The Review and Edit Policy page provides an opportunity to refine your policy.

    To help you improve your policy, Agent Cloud provides a Policy Strength score and recommendations when it creates the policy. A higher Policy Strength score means the policy is more specific, leading to more accurate detections. Recommendations typically ask for more detail or clarification of ambiguous terms to avoid assumptions about intent. Below the score are four characteristics of the policy that Agent Cloud uses to determine the Policy Strength score.

    Policy characteristicDescription
    Goal and Instructions Provides high-level instructions on what the AI judge should look for.
    Key Definitions Provides definitions for the policy terms.
    The Boundary Defines specific boundaries for the policy. Provides upper and lower limits beyond which the policy detects a violation.
    Reference Examples Provides examples of tool calls and their expected classifications — violating or safe.
    Policy characteristics that Agent Cloud determines lead to a weaker rating have a number after them. The number indicates how many recommendations are needed to strengthen the policy.
  8. Click a policy characteristic that displays a number.
    The Create Policy wizard provides recommendations to strengthen the policy.
  9. Edit the characteristics according to the recommendations.
    You can edit all the characteristics with recommendations.
  10. Click Reanalyze.
    The Create Policy wizard evaluates the policy with the edited characteristics and provides an updated rating.

    If there are new recommendations, repeat the process until the Create Policy wizard indicates that you have a strong policy.

  11. Optional: Click Test Policy.
    The Test Policy page lets you test your policy against specific data. You can either enter information manually to test your policy logic in real time, or you can perform a backtest that runs this policy against previous alerts or sessions.
    The Create Policy wizard opens the Test Policy page.
  12. In Test Type, select Backtest or Manual Input.
    Test typeDescription
    Backtest Select this to run the policy against previous alerts or sessions. In Select Sessions, specify the sessions you want to test and then click Run Test.
    Manual Input Select this to provide the type of content to evaluate against the policy. In Type, select an example scenario. The choices are:
    • Agent response: A message generated by an AI agent in reply to a user. Use this type to test whether the policy detects harmful, non-compliant, or unsafe content in agent output.
    • Full session: A complete conversation between a user and an agent, including all prompts, responses, and tool calls. Use this type to test whether the policy detects patterns that only emerge across the full interaction.
    • Tool call: An invocation of an external tool or function made by an agent during a session. Use this type to test whether the policy detects unauthorized or dangerous tool use.
    • User prompt: A message sent by a user to an AI agent. Use this type to test whether the policy detects problematic instructions or requests before the agent acts on them.

    In Message, enter the message you want to test against the policy, then click Test Policy.
  13. Click Next.
    The Create Policy wizard moves to the Policy Scope page.
  14. Determine the scope of the AI agents or tools this policy affects.
    You can use the Agents or Tools tabs on the Policy Scope page to determine which agents or tools to include or exclude from the policy.
    ScopeDescription
    All agents, or All tools The default. When selected, the policy applies to every agent or tool.

    Clicking Select Agents or Select Tools and then Edit enables you to specify which agents or tools are excluded from the policy.
    Specific agents only, or Specific tools only Clicking Specific agents only or Specific tools only and then Edit enables you to specify which agents or tools are included in the policy.
  15. Click Next.
    The Create Policy wizard displays the Finalize Policy Details page.
  16. Provide the policy details.
    FieldDescription
    Name Name for the policy
    Description Optional description for the policy
    Categories Categories to which you can assign the custom policy. These are independent from the system-provided pack categories. The available categories are:
    • Security: Defends against adversarial attacks and dangerous agent behaviors
    • Operational: Guardrails that control what the agent is allowed to do at runtime
    • Content Safety: Detects harmful, abusive, or inappropriate language in agent responses
    • Compliance: Protects sensitive data and enforces regulatory and organizational obligations
    • Configuration: Assesses the quality and correctness of how the agent is set up before it runs
    Severity The severity that Agent Cloud assigns to violations of the policy.
    Status Whether the policy is enabled or disabled
    Source Indicates that the policy judge is an LLM
    Enforcement Determines the enforcement level of the policy, Monitor, Block, or Ask. Custom policies always have an enforcement of Monitor.
  17. Click Save.

Results

The custom policy is now active in your policy inventory. New custom policies start in Monitor. Test the policy before you move it to Block. For more information, see Plan your policy rollout.
