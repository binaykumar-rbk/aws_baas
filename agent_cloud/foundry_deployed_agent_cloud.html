            Agent Cloud reads Amazon Bedrock model invocation logs from Amazon CloudWatch Logs or an Amazon S3 bucket, through an IAM role in your AWS account that Agent Cloud assumes.

          • Amazon Bedrock AgentCore deployed in Agent Cloud

            Agent Cloud reads the OpenTelemetry runtime logs that Amazon Bedrock AgentCore writes to Amazon CloudWatch, through an IAM role in your AWS account that Agent Cloud assumes.

        Agent Rewind undoes the changes that an agent action made to your data by restoring the affected objects from Rubrik backups, without rolling back the entire workload. Microsoft Foundry deployed in Agent Cloud

Agent Cloud monitors AI agents in Microsoft Foundry by ingesting activity logs from Azure Application Insights through an app registration connection.

Integrating Microsoft Foundry with Agent Cloud provides visibility into the AI agentic ecosystem at the project level. With this connection, Agent Cloud automatically discovers agents and ingests conversation history to track usage, activity, and potential errors.

Note:
Agent Cloud supports Microsoft Foundry (new) and Microsoft Foundry (classic).
Note:
Instead of the Microsoft native integration, you can monitor and govern AI agents in Microsoft Foundry (new) with the Agent Cloud gateway. The gateway can block Foundry-hosted LLMs for AI agents built outside the Microsoft Foundry (new) framework. AI agents built natively in the Foundry framework and routed through an external gateway can bypass Foundry's built-in guardrails.

Connection methods

  • A Rubrik-managed app connects a single project. For more information, see Single project connection with a Rubrik-managed app.
  • Your own app registration connects multiple projects in a single connection. For more information, see Multiple project connection with your own app registration.

Capabilities for Microsoft Foundry (new)

The following table lists what Agent Cloud supports for Microsoft Foundry (new).
Capability Support
Discovery Agents, tools, sessions, identities
Session activity User prompts, agent responses, tool calls, tool responses
Violations Yes
Monitor Yes
Block Not supported
Ask Not supported

Capabilities for Microsoft Foundry (classic)

The following table lists what Agent Cloud supports for Microsoft Foundry (classic).
Capability Support
Discovery Agents, sessions
Session activity User prompts, agent responses
Violations No
Monitor Yes
Block Not supported
Ask Not supported

For all connections, see Agent Cloud support matrix.

Requirements

Review the project, Azure account, and role requirements, including that Application Insights must be in the same region as the project. For more information, see Microsoft Foundry (new) requirements for Agent Cloud.

For Microsoft Foundry (classic), agent code must be instrumented with client-side tracing that sends traces to Application Insights, and Agent Cloud observes only instrumented agents. For more information, see Microsoft Foundry (classic) requirements for Agent Cloud.

Limitations

  • Agent Cloud cannot block actions through the Foundry connection. Block policies on this connection behave like monitor policies.
  • To block in real time, agents built outside the Foundry framework can send their model traffic through the Rubrik AI gateway instead. Agents built natively in Foundry and routed through an external gateway may bypass the built-in guardrails of Foundry.
  • Foundry (classic) captures only user prompts and agent responses from instrumented agents. It does not capture tool calls, tool responses, or system prompts.
