        • How policies work

          A policy is a named rule with a severity that Agent Cloud evaluates against your agents, tools, and sessions. When agent activity breaks a policy, Agent Cloud records a violation or an alert and, depending on the policy's enforcement mode, can stop the action.

        • Enforcement modes

          The enforcement mode of a policy determines what happens when agent activity breaks it: Monitor records an alert, Block stops the action before it runs, and Ask hands the action to the approval prompt of the agent.

        • Blocking support by connection

          Which items Agent Cloud can block, and whether Ask is supported, depends on the connection. Check this table before you set a policy to Block.

        • Agent Cloud system policies

          Agent Cloud includes multiple system policies. These policies are not enabled by default. You can enable them from the Policies page.

        • Agent Cloud policy packs

          Agent Cloud policy packs are curated collections of system policies you can add to your Agent Cloud account to enable a focused set of controls for a specific risk area, compliance framework, or industry.

        • Custom policies

          A custom policy is a rule that you write in plain English. The Semantic AI Governance Engine turns it into a policy that it judges against agent activity by intent, not by matching keywords.

Alerts and violations

Alerts and violations are the findings that your policies produce. An alert is a specific action or message that broke a policy. A violation is a standing configuration that breaks one.

For example, Agent Cloud raises a violation when an agent is configured with a delete_file tool that a policy forbids, whether or not the agent ever calls it. It raises an alert when an agent actually calls the tool. Every policy produces findings, whatever its enforcement mode. A Block policy also stops the action on connections that support blocking.

Alerts

Click Runtime > Alerts. Alerts are grouped. Select a group to view its alerts, and select an alert to open its details:

  • Overview: A reasoning summary. The agent, host, tool, identity, and application. What triggered the alert, its severity, the policy broken, and when it was raised. For policies judged by SAGE, an Alert Reasoning section explains the judgment.
  • Timeline: The session timeline around the alert.
  • Raw Reasoning: The full reasoning from SAGE for a blocked action. Available only for alerts from Block policies.

Alerts from blocked actions show a Blocked chip and are recorded as already remediated. You can select an alert to open the Alert details tray, and then select the policy violation to open the Remediate tray.

Triage alerts and violations

Alerts and violations start as Open. To change the status, click Open in the details and select one:

  • In Progress: You are investigating or addressing it.
  • Remediated: You resolved the issue or rewound the action.
  • Dismissed: You reviewed it and no action is needed.

Alerts can also be Closed, a final state that needs no further action.

To act on an alert or violation, click Remediate:

  • Rewind Action: Undo the agent action. For more information, see Rewinding an agent action.
  • Mark as Safe: Add a policy exception so that Agent Cloud allows the activity from now on. Marking as safe always adds an exception. If a single finding was a false positive but the policy should keep evaluating the same activity, set the status to Dismissed instead. For more information, see Marking alerts and violations as safe.

Viewing violation details

View details regarding policy violations, including the affected application, the tool used, and the underlying LLM model.

About this task

Agent Cloud captures and categorizes policy violations to provide visibility into risky agent actions, such as unauthorized data deletions or access to sensitive information.

Procedure

  1. Log in to RSC.
  2. Click and select Agent Cloud.
    The Agent Cloud page appears.
  3. Click Posture > Violations.
  4. Click the violation alert to view.
    Agent Cloud opens the action tray.
  5. View the violation details.
    Tab headingDescription
    Overview Displays detailed information about the policy violation, including a summary, the affected entities, and the date and time the violation was detected.
    Active Alerts Lists the alerts that are currently active due to this policy violations.
  6. Optional: Click Open and change the status of the AI agent error.
    You can choose from these statuses:
    • In Progress
    • Remediated
    • Dismissed
  7. Optional: Click Remediate > Mark as Safe.
    Agent Cloud opens the Mark Violation as Safe dialog, with the option to add this tool as an exception to the policy.
  8. Click Save.
  9. Exit the violations view.

Results

You have viewed detailed information about the policy violation.

Marking alerts and violations as safe

Mark an alert or a violation as safe when the activity it flagged is legitimate and will recur. Marking as safe creates a policy exception that suppresses future alerts, violations, and blocks for a specific tool or agent.

Before you begin

Log in with the required permissions to manage Agent Cloud policies.

About this task

When Agent Cloud detects agent activity that violates a policy, it raises an alert or a violation. If the activity was expected or acceptable for your organization, you can mark the finding as safe. Marking as safe always adds an exception: the policy is updated so that the tool or agent no longer produces alerts, violations, or blocks under it. Marking a finding as safe also creates a policy exception for the affected tool or agent and automatically dismisses all active alerts and violations that match the exception.

If a single alert or violation was a false positive but the policy should keep evaluating the same activity, do not mark it as safe. Set its status to Dismissed instead, and for a custom policy, add the case as an example so that SAGE learns from it. For more information, see Editing a custom policy using an AI judge.

Procedure

  1. Log in to RSC.
  2. Click and select Agent Cloud.
    The Agent Cloud page appears.
  3. Open the alert or violation to mark as safe.
    1. For an alert, click Runtime > Alerts, and then click the alert that you want to mark as safe.
      The alert details panel opens.
    2. For a violation, click Posture > Violations, optionally use the Violations page filters to locate the violation, and then click the violation to review.
      Agent Cloud opens the violation details tray, which includes a violation summary, the policy violated, the time detected, and the affected entities.
  4. Click Remediate > Mark as Safe.
    The Mark Alert as Safe dialog or the Mark Violation as Safe wizard opens.
  5. Select the exception to add.
    The options depend on what produced the finding. For an alert on a tool call, you can add the tool as an exception for all agents, or add the agent as an exception to the policy. For a violation, the only exception type available is a tool exception, which adds the tool as an exception to the policy.
    MethodDescription
    Define Exceptions for 'policy_name' Policy Updates the policy to allow the flagged activity in the future. You can select from one of these exceptions.
    • Select Add tool tool_name as an exception for all agents to exclude the tool that triggered the alert from the policy.
    • Select Add agent agent_name as an exception for this policy to exclude the agent that triggered the alert from the policy.
    Automatically dismiss all active alerts and violations matching this exception Selected by default. All active alerts and violations that match the exception are automatically closed, and the policy is updated to allow the flagged behavior going forward. Clear this option to close only this one finding.
  6. Click Save.
    Agent Cloud creates the policy exception, automatically dismisses all active alerts and violations that match the exception, and displays a confirmation message with the number of dismissed violations.

Results

The alert or violation is closed, and the policy allows that activity from now on. Future occurrences of this tool or AI agent usage under the selected policy no longer trigger violations, alerts, or blocks. The policy's Exceptions tab lists the exception.
