        Agent Cloud policies are the governance rules that define the acceptable behavior for your AI agents. Use them to detect risky activity and, on connections that support it, stop it.

        • How policies work

          A policy is a named rule with a severity that Agent Cloud evaluates against your agents, tools, and sessions. When agent activity breaks a policy, Agent Cloud records a violation or an alert and, depending on the policy's enforcement mode, can stop the action.

        • Enforcement modes

          The enforcement mode of a policy determines what happens when agent activity breaks it: Monitor records an alert, Block stops the action before it runs, and Ask hands the action to the approval prompt of the agent.

        • Blocking support by connection

          Which items Agent Cloud can block, and whether Ask is supported, depends on the connection. Check this table before you set a policy to Block.

        • Agent Cloud system policies

          Agent Cloud includes multiple system policies. These policies are not enabled by default. You can enable them from the Policies page.

        • Custom policies

          A custom policy is a rule that you write in plain English. The Semantic AI Governance Engine turns it into a policy that it judges against agent activity by intent, not by matching keywords.

        • Alerts and violations

          Alerts and violations are the findings that your policies produce. An alert is a specific action or message that broke a policy. A violation is a standing configuration that breaks one.

Agent Cloud policy packs

Agent Cloud policy packs are curated collections of system policies you can add to your Agent Cloud account to enable a focused set of controls for a specific risk area, compliance framework, or industry.

Policy packs let you enable a focused group of system policies as a single unit. Because some system policies can only Monitor, enabling a pack does not guarantee that every policy in it can block.

By default, Agent Cloud includes policy packs, which are groups of system policies that focus on detecting specific categories of risks, such as sensitive data exposure, prompt injection, unsafe code execution, and policy-violating model output.

Reviewing all the individual policies and deciding which apply to your account can be time-consuming, particularly for accounts that protect agents across more than one line of business. Policy packs solve this problem by grouping related system policies into named bundles that an administrator can add to or remove from an account as a single unit.

Policy pack behavior

Each policy pack contains a Rubrik-curated list of system policies that address a shared theme, such as data governance or content safety. When an administrator adds a pack to an account, Agent Cloud makes the member system policies available in the policy inventory and enables them by default. The administrator can then tune individual system policies, disable specific policies that do not apply, or add additional packs as the deployment grows.

Policy packs control which system policies are active in an account. They do not define new detection logic and they do not replace custom policies.
Attention:
A single policy can belong to more than one pack, so adding overlapping packs does not duplicate evaluations or alerts.

When to use policy packs

Policy packs scope the Agent Cloud policy inventory to the controls that matter for the workloads, regulatory environment, and risk profile of the account. Typical scenarios include the following:

  • Activating a baseline of common protections when onboarding a new RSC account to Agent Cloud.
  • Enabling a specific compliance framework, such as a responsible AI program or a data governance program, without selecting every policy individually.
  • Adding rules built for a specific industry, such as healthcare or banking, on an account whose AI agents work in that industry.
  • Layering additional protections, such as content safety or code execution safety, on top of the Essentials baseline category as new agent use cases come online.

Policy pack categories

Agent Cloud organizes policy packs into categories.

The following table describes the policy pack categories included with Agent Cloud.
Category Description
Essentials A baseline pack that contains universal controls for data exposure, prompt injection, hallucination, and privilege escalation. Agent Cloud adds the Essentials pack to new accounts automatically so that core protections are in place from day one.
Security Packs that defend against threats to AI agent integrity and the data the AI agent can reach. This category includes packs for data exposure prevention, prompt security, agent permissions and boundaries, code execution safety, and tool and plugin integrity.
Compliance and governance Packs that align AI agent activity with audit, accountability, and responsible AI requirements. You can use these packs to support internal governance programs and external regulatory obligations.
Content safety A pack that blocks toxic, profane, harassing, or impersonating output from agents that interact with end users.
Industry Packs that target the regulatory and operational requirements of a specific industry, such as healthcare or financial services.

Manage policy packs

An Agent Cloud administrator can add or remove policy packs at any time from the policy packs catalog. Adding a pack makes its member policies visible in the policy inventory and enables them by default. Removing a pack hides the policies that no other active pack provides and stops Agent Cloud from generating new alerts for those policies. Existing alerts and historical evaluation data are preserved.

To view the catalog and the policies in each pack, see Viewing the policy packs and their policies. To add a pack, see Adding policy packs to an account. To remove a pack, see Removing policy packs from an account. For the packs that are available, see Available policy packs.

Available policy packs

Information on the policy packs available on Agent Cloud.

The following table describes the policy packs that are available on Agent Cloud.
Policy pack Category Description
Agent Permissions & Boundaries Security Constrains what Agent Cloud enables an AI agent to do at runtime. It limits the AI agent to the smallest set of tools it needs to do its job, the models the agent may invoke, the environments in which the agent may perform write or destructive actions, and the commitments the agent may make on behalf of the organization.

Use this policy pack to prevent an authorized agent from operating outside its intended scope, regardless of whether the deviation is caused by a misconfigured prompt, a compromised tool description, an over-permissive model selection, or an unintended escalation in production.
AI Agent Essentials Essentials The baseline control set that Agent Cloud applies to every RSC account. It contains the universal policies that defend against the risks shared by every AI agent deployment, independent of industry, workload, or regulatory environment. Agent Cloud adds this pack to new accounts automatically so that core protections are in place from day one, and the pack remains the foundation to which all other packs build on.

Use this pack as the always-on safety net for the account. It is intentionally broad and conservative: it covers the failure modes that are most likely to cause customer-visible incidents, data exposure, or loss of trust in AI agent output, while leaving industry-specific and use-case-specific controls to the opt-in packs.
Audit & Accountability Compliance and governance Ensures that every action an AI agent takes can be traced back to a responsible party and that security-relevant events are captured in a form suitable for compliance review. This policy pack closes the gaps that ordinary logging tools leave behind when they are applied to AI agents. Because an AI agent decides for itself which model calls and tool calls to make, a single user request can lead to many downstream actions, and ordinary logs do not connect those actions back to the user or the request that caused them.

Use this pack to satisfy internal audit programs, external regulatory obligations, and incident response requirements that depend on a complete, attributable record of agent activity.
Code Execution Safety Security Inspects code that an AI agent produces, suggests, or hands off to a runtime, and detects patterns that are unsafe to run. AI agents increasingly generate code as part of normal operation, composing SQL queries, emitting shell commands, returning snippets for a developer to run, or invoking a code-execution tool directly. This pack is the control layer that sits between the output of the agent and the place where that code is actually executed.

Use this pack to prevent an agent from introducing injection vulnerabilities, executing obfuscated payloads, or driving a code-execution tool with input that has not been validated.
Coding Agent Security Security Governs AI agents whose primary function is to write, modify, or ship software, coding assistants, IDE-integrated agents, pair-programmers, and other such agents.

Coding agents run with elevated access to the tools that build the organization's software, and a single misstep can cascade far beyond the agent itself, through committed secrets, unreviewed dependency additions, and general misuse.

This pack enforces the controls specific to this class of agent, separating what a coding agent may propose from what it may actually commit, install, or deploy.

Use this pack on any AI agent that:
  • Clones, reads, edits, commits, or pushes to source repositories
  • Installs or updates dependencies
  • Authors or modifies CI/CD configuration
  • Has access to developer credentials or signing keys
  • Can trigger builds or deployments on behalf of an engineering team.
Content Safety Content safety Governs the tone, language, and self-representation of an AI agent's output. It blocks responses that would be harmful, offensive, or deceptive to the end user, and it prevents the agent from misrepresenting itself as a human. The pack is concerned with what the agent says to people, not with what the agent does in downstream systems.

Use this pack on any agent that produces output that reaches an end user, such as customers, employees, partners, or members of the public, through chat, email, voice, ticketing systems, or any other conversational surface.
Data Exposure Prevention Security Blocks the leakage of sensitive data across every surface that an AI agent touches. It inspects what the agent receives as input, what it passes into tool calls, and what it returns as output, and stops sensitive content from crossing trust boundaries it should not cross, whether outbound to an end user, sideways into a third-party tool, or upstream into a model provider.

Use this pack on any agent that is exposed to regulated data, customer data, internal business intelligence, or operational secrets, and that interacts with external models, external tools, or external users.
Data Governance Compliance and governance

Enforces the handling rules that the organization has committed to for regulated and sensitive data, applied to every AI agent interaction. Where Data Exposure Prevention focuses on stopping leaks, Data Governance focuses on whether the data was permitted to be in that interaction at all, how it was handled, where it was sent, and whether the activity is consistent with the policies the organization is accountable for upholding.

Use this pack to align AI agent activity with the data classification, residency, retention, and lawful-use rules that already govern the rest of the organization, and to produce the evidence that internal and external auditors expect.
Financial Services AI Governance Industry Tailors Agent Cloud's controls to the regulatory and operational requirements of banking, capital markets, insurance, and other financial services workloads. It addresses the specific failure modes that carry outsized risk in financial services, such as commitments made on behalf of the firm, disclosure of competitively sensitive information, and statements that can be construed as financial advice or a binding offer, and adds the recordkeeping and supervision controls that financial regulators expect.

Use this pack on any AI agent that interacts with customers, counterparties, or internal teams in a financial services context, or that has access to pricing, strategy, account, or transaction data.
Healthcare AI Governance Industry Tailors the controls of Agent Cloud to the safety, privacy, and equity requirements of healthcare workloads. It enforces the practices that healthcare regulators, accreditation bodies, and patient-safety programs expect of any AI system that touches clinical workflows, patient communications, or protected health information. The pack is derived from the Coalition for Health AI (CHAI) Responsible AI Guide and codifies its principles as runtime controls on agent behavior.

Use this policy pack on any AI agent that interacts with patients or clinicians, that handles clinical or administrative health data, or that participates in care delivery, scheduling, billing, or member-services workflows in a healthcare context.
Prompt Security Security Protects an AI agent from being given instructions it should not follow, whether those instructions come from the user prompt or from content the AI agent reads while doing its work. Modern agents take instructions from many sources beyond the user prompt, such as system prompts, retrieved documents, tool outputs, web content, email bodies, ticket fields, and the descriptions of the tools themselves, and any of those surfaces can be used to subvert the intended behavior of the AI agent. Prompt Security inspects all of them and detects attempts to override, exfiltrate, or poison the instructions the agent is acting on.

Use this pack on every agent that accepts free-form user input or that consumes content from external sources, including any agent that performs retrieval, browses the web, reads documents, or calls tools that return untrusted text.
Responsible AI Compliance and governance Aligns AI agent behavior with the cross-cutting principles that responsible AI programs commit to, such as transparency, accountability, human oversight, and the avoidance of foreseeable harm. Where industry packs codify the rules of a specific regulator and security packs defend against specific attack patterns, Responsible AI enforces the conduct standards that the organization has made to its customers, employees, regulators, and the public about how its AI systems behave.

Use this pack to operationalize the responsible AI principles of the organization as runtime controls, rather than leaving them as aspirational statements that are difficult to evidence in production.
Tool & Plugin Integrity Security Validates the tool catalog that an AI agent operates against. AI agents make routing decisions based on the names, descriptions, parameter schemas, and metadata of the tools available to them, and that surface is a security boundary in its own right. A description that is ambiguous, deceptive, contradictory, or carries a hidden instruction can cause the agent to invoke the wrong tool, leak data into the wrong destination, or follow injected guidance, even when every individual tool is itself well-behaved.

Use this pack on any agent that exposes more than a handful of tools, that consumes plugins or connectors from a third-party marketplace, or that allows tool registration to be performed by teams outside a central review function.

Viewing the policy packs and their policies

View the policy packs catalog to see which packs are available and which are added to the account, and view the policies that a pack contains, including the name, category, and current status of each policy in the account.

Before you begin

To view the system policies in a pack that is already added to the account, you must have the permission to view policies in Agent Cloud. To view the system policies in a pack that is not yet added to the account, you must have the permission to view the policy packs catalog.

About this task

Each policy pack in Agent Cloud bundles a curated set of system policies that address a shared area of agent risk or compliance. View the policies in a pack to confirm which controls the pack enables, to decide whether to add the pack to the account, or to tune an individual policy that the pack provides. The catalog also shows the number of policies that each pack contains.

Procedure

  1. Log in to RSC.
  2. Click and select Agent Cloud.
    The Agent Cloud page appears.
  3. Click Policies.
    Agent Cloud displays the Policies page.
  4. Select Policy Packs.
    Agent Cloud displays a list of the policy packs.
  5. Click View Policies to view the policies that comprise the policy pack.
    If the policy pack is not yet added, the page displays the View Policies button. If the policy pack is already added, the button is named Manage.
  6. Optional: Click the name of a policy to open the policy details page and view the policy's detection logic, severity, and tuning options.

Results

The policies in the policy pack are displayed, showing the name, category, and status of each policy.

What to do next

From the catalog, an administrator can add a pack to the account, remove a pack from the account, or open a pack to tune its member policies.

Adding policy packs to an account

Add a policy pack to an RSC account to include its system policies in the list of policies that appear on the My Policies page.

Before you begin

You must have the permission to manage policies on Agent Cloud in the RSC account.

About this task

When you add a policy pack, Agent Cloud makes the member policies available in the policy inventory on the My Policies page and enables them by default. The AI Agent Essentials pack is added to new RSC accounts automatically and all other packs are opt-in.

Procedure

  1. Log in to RSC.
  2. Click and select Agent Cloud.
    The Agent Cloud page appears.
  3. Click Policies.
    Agent Cloud displays the Policies page.
  4. Click Policy packs.
    Agent Cloud displays the Policy packs catalog, organized by category, with the status of each pack in the account.
  5. Click Add Pack to add the policy pack to the RSC account and add its policies to the My Policies page.
    You can also add the policy pack by clicking Add Pack on the View Policies details page.
    Agent Cloud adds the pack to the account, makes the member policies visible in the policy inventory, and enables the policies by default.

Results

The policy pack is added to the account, and the policies that the pack provides begin evaluating agent activity.
Note:
A single policy can belong to more than one policy pack. Adding a pack that overlaps with a pack that is already active in the account does not duplicate evaluations or alerts for the shared policies.

What to do next

To tune an individual policy, open the policy from the policy inventory or from the pack details page. To remove the pack from the account, return to the Policy packs catalog and remove the pack from the pack details page.

Removing policy packs from an account

Remove a policy pack from a RSC account. After removed, the policies the pack provides stop generating new alerts.

Before you begin

You must have the permission to manage policies on Agent Cloud in the RSC account.

About this task

Administrators can remove policy packs from a RSC account at any time. Removing a pack hides the policies that no other active pack provides from the My Policies page and stops Agent Cloud from generating new alerts for those policies. Existing alerts and historical evaluation data are preserved. Policies that another active pack also provides remain visible in the policy inventory and continue to evaluate agent activity.

Procedure

  1. Log in to RSC.
  2. Click and select Agent Cloud.
    The Agent Cloud page appears.
  3. Click Policies.
    Agent Cloud displays the Policies page.
  4. Click Policy packs.
    Agent Cloud displays the Policy packs catalog.
  5. On the card for the policy pack to remove, click and then Remove pack.
    You can also remove the policy pack by clicking Manage and then clicking Remove Pack on the View Policies details page.
    Agent Cloud displays a confirmation dialog.
  6. Click Confirm.

Results

The policy pack is removed from the account. Policies that another active pack provides remain visible in the policy inventory and continue to evaluate agent activity.
Note:
The AI Agent Essentials pack provides the universal baseline policies that Agent Cloud applies to every account. Confirm with your RSC administrator before removing this pack from a production account.

What to do next

To re-enable the coverage that was lost, add the pack again from the Policy packs catalog or add a different pack that provides the same policies.
