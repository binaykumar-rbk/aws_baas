Amazon Bedrock AgentCore deployed in Agent Cloud

Agent Cloud reads the OpenTelemetry runtime logs that Amazon Bedrock AgentCore writes to Amazon CloudWatch, through an IAM role in your AWS account that Agent Cloud assumes.

The Bedrock AgentCore integration connects Agent Cloud to Amazon Bedrock AgentCore Runtime. Unlike the Bedrock Agents integration, which ingests model invocation logs from Amazon Bedrock, the AgentCore integration ingests OpenTelemetry runtime logs written by AgentCore to Amazon CloudWatch. Each connection covers one AWS account and region, and auto-discovers all AgentCore runtimes within it.

Capabilities

The following table lists what Agent Cloud supports for Amazon Bedrock AgentCore.
CapabilitySupport
DiscoveryAgents, tools, sessions
Session activityUser prompts, agent responses, tool calls, tool responses
ViolationsYes
MonitorYes
BlockNot supported
AskNot supported

For all connections, see Agent Cloud support matrix.

Supported scope

Agent Cloud connects to AgentCore runtimes in a single AWS account and region for each connection. Log groups under /aws/bedrock-agentcore/runtimes/ are auto-discovered. Individual log groups do not require configuration.

Observability and logging

Amazon Bedrock AgentCore automatically writes OpenTelemetry runtime logs to Amazon CloudWatch under the /aws/bedrock-agentcore/runtimes/<agent_id>-<endpoint> log group path. Agent Cloud ingests these logs to display timelines of AI agent actions to support identification of policy violations or destructive actions that require remediation.

Requirements

You need at least one AgentCore runtime and IAM administrator permissions in the target AWS account. For more information, see Amazon Bedrock AgentCore requirements for Agent Cloud.

Limitations

  • One connection covers one AWS account and region. Create a connection for each additional account or region.
  • Agent Cloud cannot block AgentCore actions in real time. Block policies on this connection behave like monitor policies.
