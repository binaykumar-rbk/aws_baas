Setting up SACLs for the domain partition

Set up the System Access Control List on the domain partition to identify the actor responsible for detected actions in Active Directory.

Before you begin

You must perform this procedure with elevated privileges as a domain administrator with the SeSecurityPrivilege permission.

About this task

To audit all modification events, set up the System Access Control Lists (SACLs) on the Active Directory (AD) server or domain controller. A SACL defines the scope of auditing on AD objects and determines which actions by which users are recorded in the security event log.

Setting up a SACL is a fully reversible operation. A SACL only controls what is logged. It grants no access and does not change permissions, owner, or any other security setting on the object, and it audits modifications only.

Note:
You configure the SACL per domain. In a multi-domain forest, repeat these steps for each domain that you want to monitor.

Procedure

  1. Open the AD Administrative Center.
  2. Navigate to the domain that you want to audit and select Properties.
  3. Navigate to the Security tab and click Advanced > Auditing.
  4. Click Add to create an auditing entry.
  5. Specify the principal as Everyone, and from the Applies to list, select This object and all its descendant objects.
    Note:
    In a SACL, Everyone defines the scope of the audit, not the level of access. This setting means that Rubrik audits everyone who attempts these specific actions and does not grant permissions to users or groups.
  6. From the Type list, select Success.
  7. Select Full Control.
  8. Clear Read permissions and Read all properties so that reads are not audited.
  9. Click OK to save the auditing entry.
  10. Click Apply to start auditing all modification events.

Results

You have successfully set up SACLs to enable actor identification.
