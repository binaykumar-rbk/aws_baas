      • Kubernetes protection

        RSC protects your on-premises or cloud-native Kubernetes clusters by backing up resources you add to protection sets.

        • Deployment architecture for Kubernetes protection

          RSC serves as the control plane for Kubernetes protection. A connected Rubrik cluster stores the Persistent Volume backups.

        • Kubernetes protection images

          RSC deploys container images on your Kubernetes cluster as part of Kubernetes protection.

        • Resource requirements for Kubernetes protection components

          RSC deploys three components in the rubrik-kupr namespace on your Kubernetes cluster. Each component has default CPU, memory, and ephemeral storage requests and limits.

        • Kubernetes protection prerequisites

          There are common and specific prerequisites for Kubernetes protection.

        • Kubernetes protection requirements

          You can use Rubrik Security Cloud to secure your on-premise or public cloud Kubernetes clusters by protecting either entire Kubernetes namespaces or specific subsets within a namespace using the protection set filtering feature.

        • Kubernetes multi-networking for backup traffic

          You can configure a dedicated network for Rubrik backup and restore traffic on on-premises Kubernetes clusters to improve performance and isolate backup traffic from application traffic. This feature requires Rubrik CDM versions 9.4.2 and later.

        • Node Proxy transport for Kubernetes backups

          The Node Proxy transport routes backup and restore traffic for Rubrik Backup Agent pods, including backups of OpenShift virtual machines, over a dedicated backup network without assigning a routable IP address to each pod.

        • Kubernetes cluster onboarding

          To onboard your Kubernetes cluster, add it to your RSC domain and provide RSC with access to the cluster and sufficient permissions.

        • Least privilege configuration for Kubernetes

          You can set up your Kubernetes kubeconfig with the least privileges so that only minimal RBAC permissions are assigned to users and service accounts.

        • Kubernetes labels

          RSC integrates with Kubernetes native labels to manage data protection, enabling you to use Kubernetes labels to identify and group resources, and then associate those labels with SLA Domains.

        • Protection sets for Kubernetes cluster workloads

          A Kubernetes cluster protection set define the resources to protect on a Kubernetes cluster. A cluster protection set can include an entire Kubernetes namespace or a subset of resources within a namespace.

        • Kubernetes resource exclusion with Velero labels

          Exclude specific Kubernetes resources from RSC backup by applying a Velero label to those resources when protection set exclusion filters are not a viable option.

        • Application protection sets

          An application protection set protects enterprise workloads spanning multiple Kubernetes namespaces as a single unit.

        • Browse Kubernetes snapshots

          You can use RSC to browse the resources in a Kubernetes snapshot for protection sets and virtual machines.

        • OpenShift Virtual Machine workload

          You can use RSC to protect containers and virtual machines managed on Kubernetes OpenShift clusters.

        • Kubernetes workload protection policies

          In RSC, you can take both policy-based and on-demand snapshots of Kubernetes protection sets.

        • Kubernetes snapshot retention

          RSC allows changing the retention period of Kubernetes snapshots with the help of SLA Domains. Kubernetes snapshot retention works only with Rubrik clusters running Rubrik CDM version 7.0.2-p2 and later.

        • StorageClass mapping for Kubernetes

          StorageClass mapping provides the ability to select or define new storage tiers when restoring Kubernetes workloads to a different cluster or environment.

        • Resource transforms for Kubernetes recovery

          You can apply a resource transformation to modify a Kubernetes resource manifest during recovery without changing the original snapshot or source cluster.

ProtectionSet CRD

The ProtectionSet custom resource definition provides information about an application in the Kubernetes cluster. Rubrik Kubernetes data protection can use a ProtectionSet custom resource to protect that application.

The ProtectionSet custom resource definition (CRD) contains fields that define an application in the Kubernetes cluster that can be protected. A ProtectionSet custom resource can be used to assign an SLA Domain to protect the defined application.

The following characteristics apply to a ProtectionSet custom resource:
  • It is scoped at the namespace granularity and is part of the namespace to which the protection set belongs.
  • It can be created through kubectl.
  • It can be assigned the protection of an SLA Domain and managed backups can be initiated through that assignment. To provide this protection you assign an SLADomain custom resource to the ProtectionSet custom resource.
