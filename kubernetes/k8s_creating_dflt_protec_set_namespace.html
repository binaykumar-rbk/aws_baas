        • Kubernetes protection requirements

          You can use Rubrik Security Cloud to secure your on-premise or public cloud Kubernetes clusters by protecting either entire Kubernetes namespaces or specific subsets within a namespace using the protection set filtering feature.

        • Kubernetes multi-networking for backup traffic

          You can configure a dedicated network for Rubrik backup and restore traffic on on-premises Kubernetes clusters to improve performance and isolate backup traffic from application traffic. This feature requires Rubrik CDM versions 9.4.2 and later.

        • Node Proxy transport for Kubernetes backups

          The Node Proxy transport routes backup and restore traffic for Rubrik Backup Agent pods, including backups of OpenShift virtual machines, over a dedicated backup network without assigning a routable IP address to each pod.

Creating a default protection set for a namespace

To protect the applications and data of an entire Kubernetes namespace using RSC, create a protection set that includes the entire namespace without filtering for specific types of resources.

About this task

Creating a protection set for a subset of resources within the namespace requires creating filters to include and exclude resources from the protection set. Creating a custom protection set for a namespace contains more information about creating custom protection sets for namespaces.

Procedure

  1. Log in to RSC.
  2. Click and select Data Protection.
    RSC displays the Data Protection dashboard.
  3. On the navigation bar, hover over Inventory and click Data Center.
    RSC displays the Inventory page for Data Center workloads.
  4. Click the Kubernetes Protection card.
    RSC displays the Kubernetes page.
  5. Click Protection Sets.
  6. Click Create Protection Set.
    You can also access the Create Protection Set wizard by clicking the on the Clusters page for a Kubernetes cluster.
    The Create Protection Set wizard appears.
  7. Select a Kubernetes cluster and click Next.
    You can use the filters under Rubrik Cluster and SLA Domain to limit the Kubernetes clusters listed.
    The Select a Protection Set Type page appears.
  8. Select Default protection set to configure a custom default protection set that includes all the existing and future non-system namespaces.
    You cannot use this section if the Kubernetes cluster includes any virtual machines.
  9. Click Next.
    The Confirm Protection Set Details page appears.
  10. Review the protection set details and confirm that the kinds and labels you specified in the filters exist in your Kubernetes cluster.
  11. Click Create.

Results

The new Kubernetes protection set includes the applications and data of the entire Kubernetes namespace to protect, and it is ready for SLA Domain assignment.
