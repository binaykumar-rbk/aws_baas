          Rubrik Security Cloud offers protection services for the Active Directory forest hierarchy. You can protect and recover the entire forest hierarchy in the event of a disaster or ransomware attack.

        • Active Directory domains and domain controllers

          You can protect and recover Active Directory domains and domain controllers by using the protection services offered by Rubrik Security Cloud.

          • Discovery of AD domains and domain controllers

            When you add an AD domain controller to a Rubrik cluster as a Windows host, RSC discovers the AD domain of the domain controller and the associated domain controllers of that AD domain. This enables you to start protecting the domain controller you added.

          • Active Directory inventory management

            The Active Directory inventory provides a summary of the actions involved in protecting the AD domain controllers in RSC. You can manage your domains and domain controllers using the information available in the AD inventory.

          • Active Directory domain controller protection

            To protect the information on your AD domain controllers by applying RSC data protection policies, you can assign SLA Domains to the domain controllers.

          • Active Directory snapshots

            RSC protects and manages data by taking snapshots of the domain controller. You can take an on-demand snapshot, or you can configure an SLA Domain to take scheduled snapshots.

Restoring to an original domain controller

As an RSC user with the required privileges, restore domain controller data to the same domain controller if the data is corrupted and you want to restore it to a last known good state. You can also use this recovery type if you want to recover the deleted objects.

Before you begin

You must have Restore over original data management recovery privileges.

Procedure

  1. Log in to RSC.
  2. Click and select Data Protection.
    The Data Protection dashboard appears.
  3. On the navigation bar, select Inventory > Identity > Active Directory Inventory > All > Active Directory.
    The Active Directory inventory dashboard appears and displays a list of AD domains.
  4. Click Domain Controllers and click a domain controller name.
    You can also select a domain controller associated with a specific AD domain on the Domains tab by clicking View DCs in the Domain controllers field for a specific AD domain.
    The Domain Controller details page appears.
  5. Select a snapshot from the calendar view.
    The Snapshot details appear.
  6. Open for the snapshot and select Recover.
    The Active Directory Recovery page appears.
  7. Select the recovery type as Domain controller recovery and click Next.
    If the snapshot contains any files that are marked as malicious, RSC requests an acknowledgment to proceed with the recovery. Select the check box at the bottom of the page to acknowledge and proceed with the recovery of malicious files.
    The Select Recovery Destination page appears.
  8. Select Restore to original domain controller and click Next.
    The Select Host Recovery Type page appears.
  9. Select an option for host recovery type.
    OptionDescription
    Non-authoritative Recovers the domain controllers with network configuration to get the latest update from the existing working domain controller. The restored domain controller retrieves the latest changes from the schema master.
    Authoritative Recovers the domain controller information based on the selected backup and overwrites all recent changes. The domain controller becomes a replica of the schema master for all other domain controllers. All other domain controllers will be recovered with the network configuration required to get the latest updates from the working domain controller.
  10. When using the authoritative option, select the type of authoritative recovery.
    OptionDescription
    Perform authoritative recovery of SYSVOL Specifies that the restored copy of SYSVOL is authoritative for the domain. As a result, the SYSVOL on this domain controller is replicated to all the other domain controllers of the domain after recovery.
    Perform authoritative recovery of all AD files Specifies that the restored copy of AD objects is authoritative for the domain. As a result, the AD objects on this domain controller are replicated to all the other domain controllers of the domain after recovery.
    You can also select both of the authoritative recovery options.
  11. When using the authoritative option, select the acknowledgment to confirm that you understand the changes that will take place as part of the authoritative recovery type.
  12. Click Next.
    The Recovery Confirmation page appears.
  13. Review your selections and click Recover.
    If you have created a quorum authorization policy for this operation, you are required to submit a request for quorum authorization.
  14. (Quorum authorization policy) Select a run type option.
    OptionDescription
    Automatically schedule Schedules the action to automatically run after approval.
    Manually schedule Schedules the action to run within 24 hours after the approval. Actions not run 24 hours after approval will expire.
  15. (Quorum authorization policy) Click Submit Request.
    RSC submits the request for quorum authorization. To track the status of the request, navigate to Data Protection > Events > Quorum Authorization.

Results

RSC starts the recovery for the selected snapshot and recovers the domain controller data to the same domain controller.

If you have created a quorum authorization policy, RSC executes the recovery according to the selected run type option after the request is approved.

After quorum approval, track the progress of the recovery on the Events tab of the domain controller.
