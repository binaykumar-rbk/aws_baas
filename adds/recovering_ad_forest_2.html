Recovering an AD forest

When a ransomware attack or disaster occurs, recover the entire Active Directory forest to restore all of its domains. RSC provides a master wizard that combines all the steps to recover the domains.

Before you begin

Ensure the following:

  • You have purchased the RSC Identity Recovery license.
  • The user account has the exportFiles on domain controller (DC), forestRestore on forest, and provisionOnInfra on target host privileges to recover the Active Directory (AD) forest to an alternate host.
  • The user account has the restoreToOrigin, exportFiles on DC, and forestRestore on forest privileges to recover the AD forest to the original host.
  • The user account has Export snapshots and Restore over original data management recovery privileges.
  • For Identity first recovery, you have met the prerequisites described in Identity-first recovery prerequisites, including the minimum Rubrik CDM version.
  • For alternate host recovery, you have met the prerequisites described in AD alternate host recovery prerequisites.
  • For AD host promotion, the host is on a Rubrik cluster running CDM versions 9.4.1 and later, and you have met the prerequisites described in AD host promotion prerequisites.

Procedure

  1. Log in to RSC.
  2. Click and select Data Protection.
    The Data Protection dashboard appears.
  3. On the navigation bar, select Inventory > Identity > Active Directory Inventory > All > Active Directory.
    The Active Directory inventory dashboard appears and displays a list of AD domains.
  4. Select a forest and click Recover Forest.
    The Active Directory Recovery wizard appears.
  5. Select Forest recovery and click Next.
  6. Click Start Recovery.
  7. On the Recovery Period page, select a recovery period from which to locate snapshots and click Next.
    OptionDescription
    Snapshots before custom time Finds snapshots captured before a custom time. In Before, select a date, and in At, enter a time
    Latest snapshots Uses the latest snapshots for all domains, captured within a 24-hour window
  8. Configure domains for recovery.

    RSC selects a domain controller for each domain based on your chosen point in time for recovery. You can configure each domain to select a different domain controller for recovery.

    Note:
    You must configure each domain in the forest before you proceed with the recovery.

    You can use Configure in the Configuration column to select a different domain controller for each domain. After you complete this, you can proceed with the AD forest recovery.

    You can click Reset Configuration if you want to undo the configurations you have made. The Reset Configuration option appears only when you select a configuration that increases the recovery risk compared to the default configuration provided by RSC.

  9. For each domain in a forest, click Configure and select the recovery option.
    OptionDescription
    Recover DCs only Configures only the recovery settings for the domain
    Recover DCs and promote hosts Configures the recovery settings for the domain, and then configures settings to promote hosts to act as domain controllers
  10. For Recover DCs and promote hosts, select the host promotion method.
    OptionDescription
    Promote via replication Copies all data on the DC to the promoted host over the network
    Promote using an Install From Media (IFM) package Creates an IFM package from a snapshot of the DC and uses it to copy the DC's data to the promoted host
  11. Optional: To change the recovery method for a domain controller, click in the Recovery Method column.
    1. In the Edit Recovery Configurations panel, select a recovery method.
      • Identity first recovery (recommended)
      • System state recovery
      • Bare metal recovery
      For more information, see Comparison of AD recovery methods.
    2. Optional: In Select a Cluster, select the cluster from which you want to select a DC snapshot.
      When you change the cluster, RSC selects a snapshot on that cluster based on the point in time for recovery.
    3. Click Save.
  12. Click Next.
    To recover to an alternate Windows host, use the Select Target Host page to choose your recovery method and target host. The target hosts available for selection depend on the selected recovery method.

    When there is no alternate Windows host configured, you can add a Windows host to the Rubrik cluster from Data Sources in the Settings menu.

  13. Optional: In Retain IP Address Of, select the option from which you want to retain the IP address.
    You can retain the IP address of either the target host or the source DC to avoid losing connection to the target host after recovery. After the recovery, the target host uses the selected IP address and network settings.

    RSC supports retaining IP addresses for system state recovery of snapshots taken on Rubrik clusters running Rubrik CDM versions 9.4.1 and later and for bare metal recovery on Rubrik CDM versions 9.4.1-p1 and later.

  14. In the Target Host column, click Select to select a target host and check its compatibility.
    Note:
    RSC checks the compatibility of the target host from Rubrik CDM versions 9.5.2 and later.
    The Select Target Host to Check Compatibility page appears.
  15. Select a target host from the dropdown list and click Done.
    After you select the target host, RSC checks whether the target host is compatible with the domain controller. To ensure compatibility, RSC verifies certain target host configurations that are independent of the snapshot, and matches other configurations against the source DC snapshot. You can proceed with the recovery flow while the check is still running. You can view the check results from the Target Host column.
    Note:
    Ensure the target host configuration matches the DC settings at the specific point in time selected for recovery. Mismatched configuration may cause the recovery to fail. You can review the DC configurations on this page. RSC displays DC configurations for snapshots taken on Rubrik clusters running CDM versions 9.4.1 and later. You can also view details of each configuration mismatch from Rubrik CDM versions 9.5.2 and later. All compatibility checks run on the target host and fall into two categories:
    • Checks that verify target host configurations match the source DC snapshot configuration.
    • Checks that verify configurations required on the target host for the recovery to proceed.

    RSC displays missing checks for items where verification cannot be completed. For more information on the compatibility checks, see AD alternate host recovery compatibility checks.

    Select the checkbox to acknowledge that you want to proceed with the recovery even after the compatibility check has failed or if you have stopped the checks.

  16. Optional: Click Edit DC Selection to select a different domain controller for recovery and click Save.
    RSC selects a domain controller for recovery based on your recovery reason. When other domain controllers are available, you can select a different domain controller for recovery from the Edit DC Selection page.
  17. Optional: Click Configure Unselected Domain Controllers to either erase the metadata or leave the metadata intact for the unselected domain controllers of a specific domain, and click Save.
    RSC erases the metadata of the AD object and the DNS entries related to the domain controller. However, RSC provides an option to leave the metadata intact for the unselected domain controllers.
  18. Click Next.
    RSC prompts you to enter administrator credentials or to create a new DSRM password, depending on the recovery method you selected.
  19. Optional: On the Create Password for DSRM Admin Account page, enter a unique password for the DSRM admin account and click Next.
    Store the password securely. The password must meet the minimum length and complexity requirements that your organization defines.
    Note:
    Identity first recovery requires you to set a new Directory Services Restore Mode (DSRM) password for the recovered domain controller. System state recovery and bare metal recovery restore the DSRM password from the snapshot, but Identity first recovery provisions a fresh target host, so you must provide a new password. With the DSRM password, you can start the domain controller in a safe mode that runs only a limited set of services for AD maintenance and recovery.
  20. Optional: On the Enter administrator credentials page, enter the current credentials of an administrator account in Current Username and Current Password, and click Next.
  21. For AD host promotion, click Select Hosts.
    The Select Hosts to Promote wizard appears.
  22. In Select Hosts to Promote, select the hosts from the list of Windows hosts that you want to promote as domain controllers, and click Save.
    The Create Password for DSRM Admin Account page appears.
  23. Enter the DSRM password for each host that you selected.
    The password must meet the required criteria.

    For the Promote using an Install From Media (IFM) package option, you must also select the DC that has the snapshot to promote the Windows host to a domain controller.

  24. Optional: Click Edit Hosts to select different hosts or make any modifications to the host selection and click Save.
  25. Click Next.
    Configure each domain in the AD forest before you continue.
    RSC marks the configuration for the selected domain as completed.
  26. Select an option to configure and recover DNS.
    • Configure DNS automatically
    • Enter IP Addresses for DNS
    • Leave DNS settings intact
    For Enter IP Addresses for DNS, enter the IP addresses in IP Address, separated by commas.
    Based on your reason for recovery, RSC selects the recovery settings automatically to recover the selected forest. You can change the settings by configuring them manually.
  27. Optional: Click Configure Advanced Settings, change the settings, and click Save.
    For more information, see AD forest recovery advanced settings options.
  28. Click Next.
    The Recovery Confirmation page appears.
  29. Review your selections and click Recover.
    If you have created a quorum authorization policy for this operation, you are required to submit a request for quorum authorization.
  30. (Quorum authorization policy) Select a run type option.
    OptionDescription
    Automatically schedule Schedules the action to automatically run after approval.
    Manually schedule Schedules the action to run within 24 hours after the approval. Actions not run 24 hours after approval will expire.
  31. (Quorum authorization policy) Click Submit Request.
    RSC submits the request for quorum authorization. To track the status of the request, navigate to Data Protection > Events > Quorum Authorization.

Results

RSC starts the recovery for each domain and recovers the domain controller data to the target host.

If a host promotion fails, the AD forest recovery still completes with warnings.

If you have created a quorum authorization policy, RSC executes the recovery according to the selected run type option after the request is approved.

After quorum approval, track the progress of the forest recovery on the forest inventory page.

What to do next

If you performed a disaster recovery and want to protect the recovered forest, re-establish the AD forest protection, as described in Re-establishing AD forest protection after recovery.
Related concepts
  • Active Directory forest
    Rubrik Security Cloud offers protection services for the Active Directory forest hierarchy. You can protect and recover the entire forest hierarchy in the event of a disaster or ransomware attack.
  • AD forest protection
    To protect and recover the information from the Active Directory domain controllers in a forest hierarchy, you can assign an SLA Domain at the forest level. You can apply the data protection policies and recover the entire forest hierarchy using the automated forest recovery that RSC provides.
  • Quorum authorization for Active Directory
    Quorum Authorization protects Active Directory operations by requiring multi-user approval before an administrator can run an action, preventing a single administrator from unilaterally performing destructive or high-impact tasks.
  • Identity-first recovery for AD forest
    Rubrik recommends the identity-first recovery method to recover an Active Directory forest. RSC extracts only the identity data from a domain controller snapshot and reintroduces it into a fresh Windows target, decoupling the recovery from the source operating system.
Related reference
  • AD domain controller recovery options
    With RSC, you can recover Active Directory domain controller snapshots using either granular recovery or domain controller recovery options.
  • AD forest recovery advanced settings options
    While initiating Active Directory forest recovery process, RSC provides an option to configure the advanced settings for Windows time service, global catalog servers, and reset KRBTGT password.
  • AD forests and domains information
    Information about the Active Directory forest and domains discovered by RSC. You can view the information about Active Directory forests and domains and manage protection for the domains by assigning an SLA Domain.
