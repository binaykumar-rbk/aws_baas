Resolving the DNS debug log file path

Resolve DNS debug log file path issues on a recovered domain controller by verifying and correcting the LogFilePath registry value.

Before you begin

Ensure you meet the following requirements:
  • System state recovery to the target virtual machine is complete.
  • You have confirmed that the DNS Service is not running on the recovered domain controller.
  • You have local administrator access to the recovered domain controller.

Procedure

  1. Verify that the DNS Service is not running.

    Run the following PowerShell command:

    Get-Service DNS
  2. Check for Event ID 7031 in the System Event Log.
    Open Event Viewer and navigate to Windows Logs > System. Look for errors from the Service Control Manager referencing the DNS service.
  3. Check the current LogFilePath registry value.

    Run the following PowerShell command:

    Get-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\DNS\Parameters" `
    -Name "LogFilePath" -ErrorAction SilentlyContinue

    If the output shows a path that does not exist on this machine, for example, E:\DNSLogs\dns.log where the E:\ drive is not present, this confirms the issue.

  4. Fix the LogFilePath value using one of the following options.
    OptionWhen to use
    Remove the custom path Use this option for the quickest fix. Deleting the LogFilePath value causes DNS to fall back to the default path %systemroot%\System32\Dns\Dns.log, which is guaranteed to exist. Run the following command:
    Remove-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\DNS\Parameters" `
    -Name "LogFilePath"
    Create the missing directory Use this option if you want to preserve the original custom log path. Run the following commands to create the directory that the path points to:
    $logFilePath = (Get-ItemProperty -Path `
    "HKLM:\SYSTEM\CurrentControlSet\Services\DNS\Parameters" `
    -Name "LogFilePath").LogFilePath
$dir = Split-Path $logFilePath -Parent
New-Item -ItemType Directory -Path $dir -Force
    Update to a new valid path Use this option if you want to redirect DNS debug logging to a different location that exists on the target machine. Run the following commands, replacing the path with your desired location:
    New-Item -ItemType Directory -Path "C:\DNSLogs" -Force
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\DNS\Parameters" `
    -Name "LogFilePath" -Value "C:\DNSLogs\dns.log"
  5. Start the DNS Service. 
    Start-Service DNS
  6. Verify that the DNS Service is running and confirm the active log file path. 
    Get-Service DNS
Get-DnsServerDiagnostics | Select-Object LogFilePath, EnableLoggingToFile
    The DNS Service status shows Running and the LogFilePath reflects the corrected path.

Results

The DNS Service is running on the recovered domain controller. Name resolution for the domain is restored.
