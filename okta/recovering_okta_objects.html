Recovering Okta objects

Recover required Okta objects using automated or on-demand snapshots of your Okta tenant when a critical object is accidentally deleted or changed.

Before you begin

  • Understand the recovery scope, multi-valued data rules, user status recovery rules, and group rules recovery behavior, as described in Relationship restore scope, Recreate objects and restore relationships, Multi-valued data recovery rules, User status recovery rules, and Okta group rules recovery.
  • To recover an authorization server, review the recovery considerations and post-recovery steps, as described in Considerations for recovering authorization servers.
  • To recover objects to a different Okta tenant, review the cross-tenant recovery overview, configuration requirements, and limitations, as described in Okta cross-tenant recovery, Okta cross-tenant recovery configuration, and Okta cross-tenant recovery limitations.
  • To recover objects to a different Okta tenant, follow the steps in Recovering Okta directory objects to a different tenant.

Procedure

  1. Log in to RSC.
  2. Click and select Identity Resilience.
    The Identity Resilience dashboard appears.
  3. On the navigation bar, click Protection > Inventory.
    The Inventory page appears.
  4. On the Inventory page, select the Okta inventory card.
    The Okta tenants page appears and displays a list of Okta tenants.
  5. Click the name of an Okta tenant.
    The tenant Overview page appears, displaying the Snapshots card in month view.
  6. On the Snapshots card, select a day that has a green dot.

    A green dot indicates that RSC successfully captured a snapshot on that day.

    The Snapshots card displays the Day view, listing the snapshots taken that day.
  7. Hover over the snapshot you want to use for recovery and click Recover.
    The Okta Granular Recovery wizard displays the Select Recovery Entity page.
  8. Select Directory objects and click Next.
    The Recovery Destination page appears.
  9. Select Same tenant recovery and click Next.
    The Select Objects to Recover page appears.
  10. Select the objects you want to recover and click Next.
    You can select the objects from the supported objects displayed on the page. RSC discovers the related objects and their relationships for each supported object type.
    The Relationship Restore Scope page appears.
  11. Select a restore scope to recover the interconnected objects.
    Restore scopeDescription
    Restore and recreate Restores the selected objects, recreates any missing directly-related objects from the backup, and re-links all related objects. You confirm the related objects to recreate in the next step.
    Restore and re-link Recovers the selected objects and re-establishes relationships with linked objects that exist in the live tenant. RSC does not recover relationships with related objects that no longer exist in the live tenant.
    Restore only Recovers the selected objects without re-establishing any group memberships, policy assignments, or other relationships.
  12. Click Next.
    • If you selected the Restore and recreate option, the Select Objects to Recreate page appears.
    • If you selected the Restore and re-link option or the Restore only option, the Recovery Preferences page appears.
  13. For Restore and recreate, in Select Objects to Recreate, select the related objects you want to recreate and click Next.
    If you selected a group for recovery, a Users in Group Name entry appears in the related objects table. You can select this object to recover the users in that group. You can also click View next to the entry to review the list of users that will be recreated.
    Note:
    If you choose to recover users in a group, each recovered user is restored to the state they were in when the snapshot was taken.
    The Recovery Preferences page appears.
  14. In Recovery Preferences, under Multi-Valued Data Recovery Rules, select how you want to resolve conflicts for relationships and attributes that have multi-valued data.
    OptionDescription
    Overwrite live values Recovers the object values from the backup copy and overwrites the live copy with the object values in the backup copy.

    Effect on live data: RSC removes any new values that were added after the snapshot was taken. The object returns to the exact state it was in at the time of the backup.
    Merge with live values Recovers the object values from the backup copy and merges them with the existing values of the live copy.

    Effect on live data: RSC retains the object values that were added after the snapshot was taken, combining the historical state with the current state.
  15. Optional: If you selected Applications or Identity Providers, under Authentication Settings Recovery, select how you want to handle authentication settings during recovery.
    OptionDescription
    Keep live authentication settings Preserves the authentication settings currently on the live Okta tenant, including secrets, signing keys, and third-party trust configurations.

    This is the default option.
    Overwrite live authentication settings Replaces the current authentication settings with those from the snapshot.

    You may need to update third-party trust configurations manually after recovery.
  16. Click Next.
    • If at least one selected user was in a Staged or Locked Out status when the snapshot was taken, the User Status Settings page appears.
    • Otherwise, the User Activation and Password Settings page appears.
  17. In User Status Settings, select how you want to recover the users who were in a Staged status, and then click Next.
    This page appears only when at least one selected user was in a Staged or Locked Out status when the snapshot was taken.
    OptionDescription
    Smart recovery Updates the attributes of an existing live user without changing the current status of that user. If the Staged user was deleted from the live tenant, RSC recreates the user in the Staged status. This is the default option.
    Full state recovery RSC deletes the existing user from the live tenant and recreates the user to restore the original Staged status. This option is destructive.
    RSC recovers each user who was in a Locked Out status to the Suspended status, because Okta does not support setting the Locked Out status directly. After recovery, an administrator must manually activate these users.
    The User Activation and Password Settings page appears.
  18. In User Activation and Password Settings, select the method to set passwords for recreated users or deleted users being restored.
    OptionDescription
    Trigger activation email Sends a link to the primary and secondary email addresses of the recreated user, enabling that user to set a new password and activate the account.
    Set password manually Enables you to manually set temporary passwords for recreated users. RSC does not store these passwords and you must securely share them with the users yourself.
    All deleted users being recreated require a new password to access their accounts.
  19. Optional: Enable Reset multi-factor authentication (MFA) to require users to re-enroll in MFA when resetting their password.
  20. Click Next.
    The Okta Granular Recovery Confirmation page appears.
  21. Review all your selections and click Recover.

Results

RSC starts the recovery for each selected object and recovers the related objects and their relationships to the live tenant according to the selected recovery scope.
