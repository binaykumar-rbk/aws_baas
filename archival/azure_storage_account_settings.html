Azure storage account settings

Configure an Azure storage account with specific settings in the Azure portal before creating an Azure archival location in Rubrik.

Rubrik CDM requires an Azure storage account configured with specific settings described in the following tables. The settings are classified by tabs as they appear on the Azure storage account creation page. For all other Azure storage account settings, the default values are acceptable. For more information about how to create an Azure storage account, see Microsoft documentation.

Warning:
You must not use lifecycle policies outside of RSC to move Azure archival data to an offline storage tier. Rubrik requires all data and metadata to remain in an online tier unless Rubrik explicitly tiers the data. Using third-party tools to move data to an offline tier causes restore failures and makes archival locations unavailable, stopping all archival processes. Re-enabling access might require coordinating with the cloud vendor to rehydrate the data, as there is no automated mechanism to permanently rehydrate the data to an online storage tier. Offline storage tiers include the Azure Archive storage tier.

Basics tab

Section Setting Description
Project details Subscription The subscription for the new storage account.
Resource group A new or existing resource group within the selected subscription.
Instance details Storage account name A unique name for the new storage account.

The storage account name can be between 3 and 24 characters long and can contain numbers and lowercase letters only.

This is the value for the Storage Account Name field when configuring an Azure archival location for a Rubrik cluster.
Region The geographical region for the storage account.
Performance The type of storage account.

Rubrik CDM supports archiving only to the Standard general-purpose V2 Azure storage account.
Redundancy The redundancy level that is applicable to the type and region of the storage account.

Advanced tab

Section Setting Description
Blob storage Access tier A setting based on the frequency of accessing archived data.

Rubrik CDM supports the Hot, Cool, and Cold access tiers of Azure.

Setting the access tier means that Rubrik uploads all data and metadata directly into the selected tier.

To tier data to the Archive tier, configure Storage Tiering in the SLA Domains that use this Azure archival location. Do not configure Azure lifecycle policies to tier data to the Archive tier for these archival locations outside Rubrik.
Security Permitted scope for copy operations The setting that controls which storage accounts can copy data to this storage account. When you use archival consolidation through cloud compute on an Azure archival location, set this to From any storage account. Other values, such as restricting copies to the same Microsoft Entra tenant, block the copy operations that archival consolidation requires and cause consolidation jobs to fail.

Networking tab

You can accept the default settings or configure them according to your requirements.

Data protection tab

Section Setting Description
Tracking Enable versioning for blobs When a blob is overwritten, blob versioning automatically saves the state of the blob in a previous version.

For Rubrik clusters running Rubrik CDM versions 9.1 and later, enabling this setting is required for blob-level immutability in Azure archival locations.

Rubrik clusters running Rubrik CDM versions earlier than 9.1 do not support blob-level versioning for archiving and require that you disable this setting for the storage account.
Access control Enable version-level immutability support For Rubrik clusters running Rubrik CDM versions 9.1 and later, this setting is required to enable blob-level immutability in archival locations created using this storage account.

Setting Description

You can accept the default option of using Microsoft-managed keys for encryption.
